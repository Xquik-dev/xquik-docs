`POST https://xquik.com/api/v1/x/accounts/bulk-retry`

<Callout icon="circle-check" color="#16a34a">

**Free.** This endpoint does not consume credits.

</Callout>

<Warning>

This takes a dashboard session, or a key with the **Connect X accounts** permission. Turn it on at [dashboard.xquik.com/api-keys](https://dashboard.xquik.com/api-keys). Full access doesn't include it. A key without it gets `403 x_account_connect_permission_required`. OAuth tokens and MCP tools get `403 session_required`.

</Warning>

<Info>

Bulk retry clears only `transient` and `automated` login-failure states. It does not update passwords, TOTP secret keys, passkeys, or email challenges. It does not update locked or suspended accounts either. Use re-authentication or reconnect for credential and 2FA fixes. Resolve locks or suspensions on X first.

</Info>

This route clears temporary login-failure state. Those accounts retry on the next read, write, monitor, or account action. Use it when the dashboard shows accounts with temporary issues.

<section>

## What gets retried

<CardGroup cols={1}>

  <Card title="Xquik clears temporary issues" icon="refresh-cw">

    Xquik clears accounts whose stored failure reason is `transient` or `automated`. These accounts become eligible to reconnect on their next use.

  </Card>
  <Card title="Xquik skips credential fixes" icon="key-round">

    Accounts that need fresh credentials or a security challenge stay unchanged. Use [Re-authenticate](/api-reference/x-accounts/reauth) or reconnect the account instead.

  </Card>
  <Card title="X restrictions stay blocked" icon="shield-alert">

    Locked and suspended accounts stay unchanged. Resolve the restriction on X first, then re-authenticate or reconnect if needed.

  </Card>
  <Card title="Response is an aggregate" icon="list-checks">

    The API returns only `cleared`, the number of accounts reset for retry. Call [List X Accounts](/api-reference/x-accounts/list) before and after if you need per-account status.

  </Card>
</CardGroup>

The dashboard button works the same way. It appears when accounts have temporary issues. After you confirm, it clears retryable failures and refreshes the account list. It does not reconnect the accounts immediately.

## Headers

| Header      | Type     | Required       | Description                                                                                                       |
| ----------- | -------- | -------------- | ----------------------------------------------------------------------------------------------------------------- |
| `x-api-key` | `string` | Or `Cookie`    | An API key holding the Connect X accounts permission.                                                             |
| `Cookie`    | `string` | Or `x-api-key` | Your signed-in dashboard session cookie, `__Host-xquik_session`.                                                  |
| `Origin`    | `string` | With `Cookie`  | Must be `https://dashboard.xquik.com`, sent with `Sec-Fetch-Site` set to `same-origin`. The dashboard sends both. |

</section>

<section>

## Body

| Body parameter | Type       | Required | Description                                                                                                                                                                                                                                                               |
| -------------- | ---------- | -------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `accountIds`   | `string[]` | No       | IDs of the X accounts to retry, from 1 to 1000. Each ID can be a number or start with `xacct_`. Leave the body out to retry every account with a temporary failure. Accounts that failed for another reason stay as they are. So do accounts that belong to someone else. |

</section>

## Response

### 200 OK

| Field     | Type      | Description                           |
| --------- | --------- | ------------------------------------- |
| `cleared` | `integer` | Number of accounts cleared for retry. |

```json
{
  "cleared": 3
}
```

### 401 Unauthenticated

`{ "error": "unauthenticated", "message": "Missing or invalid API key" }`

{"\n"}

Missing or invalid API key.

### 429 Rate limited

Wait for the `Retry-After` value before retrying account recovery again.
