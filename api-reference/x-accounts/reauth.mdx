<LlmsDirective />

`POST https://xquik.com/api/v1/x/accounts/{id}/reauth`

<Callout icon="circle-check" color="#16a34a">

**Free.** This endpoint does not consume credits.

</Callout>

<Warning>

This takes a dashboard session, or a key with the **Connect X accounts** permission. Turn it on at [dashboard.xquik.com/api-keys](https://dashboard.xquik.com/api-keys). Full access doesn't include it. A key without it gets `403 x_account_connect_permission_required`. OAuth tokens and MCP tools get `403 session_required`. With a key, your backend receives the new X password. Read [your duties](/guides/connect-x-accounts-for-your-users#your-duties) first.

</Warning>

<Note>

Use this when an account session expires or X requires re-verification.

</Note>

Omit `totp_secret` to reuse the saved key. Send a replacement only if X
changed or rejected the saved key.

Re-authentication does not guarantee the same public IP. Xquik does not support custom,
dedicated, or user-supplied proxies.

<CodeGroup>

```bash cURL
curl -X POST https://dashboard.xquik.com/api/v1/x/accounts/3/reauth \
  -H "Cookie: __Host-xquik_session=YOUR_SESSION_COOKIE" \
  -H "Origin: https://dashboard.xquik.com" \
  -H "Sec-Fetch-Site: same-origin" \
  -H "Content-Type: application/json" \
  -d '{"password": "<ACCOUNT_PASSWORD>"}' | jq
```

```javascript Node.js
const response = await fetch("https://dashboard.xquik.com/api/v1/x/accounts/3/reauth", {
  method: "POST",
  headers: {
    Cookie: "__Host-xquik_session=YOUR_SESSION_COOKIE",
    Origin: "https://dashboard.xquik.com",
    "Sec-Fetch-Site": "same-origin",
    "Content-Type": "application/json",
  },
  body: JSON.stringify({
    password: "<ACCOUNT_PASSWORD>",
  }),
});
const data = await response.json();
```

</CodeGroup>

<Accordion title="Replace the saved TOTP secret">

Send `totp_secret` only when the saved key no longer works.

```bash cURL
curl -X POST https://dashboard.xquik.com/api/v1/x/accounts/3/reauth \
  -H "Cookie: __Host-xquik_session=YOUR_SESSION_COOKIE" \
  -H "Origin: https://dashboard.xquik.com" \
  -H "Sec-Fetch-Site: same-origin" \
  -H "Content-Type: application/json" \
  -d '{
    "password": "<ACCOUNT_PASSWORD>",
    "totp_secret": "<REPLACEMENT_TOTP_SECRET>"
  }' | jq
```

</Accordion>

| X account recovery column | Request or response source    | Recovery rule                                          |
| ------------------------- | ----------------------------- | ------------------------------------------------------ |
| Account ID                | Path `{id}` and response `id` | Require both IDs to match.                             |
| Current password          | Request `password`            | Send it only to this reauthentication request.         |
| Saved TOTP key            | Omitted `totp_secret`         | Reuse the stored authenticator secret.                 |
| Replacement TOTP key      | Request `totp_secret`         | Send the base32 key, never a 6-digit code.             |
| X username                | Response `xUsername`          | Confirm the recovered profile.                         |
| X user ID                 | Response `xUserId`            | Store it. It stays the same when the username changes. |
| Account state             | Response `status`             | Require `active` before write actions.                 |
| Login health              | Response `health`             | Require `healthy` before durable actions.              |

## Headers

| Header         | Type     | Required       | Description                                                                                                       |
| -------------- | -------- | -------------- | ----------------------------------------------------------------------------------------------------------------- |

<section>

## Body

| Body parameter | Type     | Required | Description                                                                                                              |
| -------------- | -------- | -------- | ------------------------------------------------------------------------------------------------------------------------ |
| `password`     | `string` | Yes      | Current password for the X account.                                                                                      |
| `totp_secret`  | `string` | No       | Replacement Authenticator App TOTP secret. Omit it to reuse the saved key. Send the base32 secret, not the 6-digit code. |
| `email`        | `string` | No       | Email for the X account. Updates the stored email during re-authentication.                                              |
| `connection_attempt_id` | `string` | No | Your own attempt ID, `xatt_` and 32 lowercase hex characters. Read the result with it if the response never arrives. |

</section>

<section>

## 2FA re-authentication

Xquik reuses the saved TOTP secret by default. Send `totp_secret` only when
replacing that key. Never send a 6-digit code, backup code, passkey, or security
key prompt.

{"\n"}

If you never saved the secret key, reset the authenticator app setup before re-authenticating. Do the same if X rejects the current one.

<CardGroup cols={1}>

  <Card title="Saved key still works" icon="clipboard-check">

    Omit `totp_secret`. Xquik reuses the encrypted key saved during connection.

  </Card>
  <Card title="Key is missing" icon="rotate-ccw">

    X shows the text secret only during Authentication App setup. Turn Authentication App off, then on again. Copy the new key, then finish setup on X.

  </Card>
  <Card title="Key was rejected" icon="triangle-alert">

    Treat the old TOTP secret as stale. Reset Authentication App setup on X and save the new long key. Finish 2FA confirmation, then re-authenticate.

  </Card>
</CardGroup>

1. Open X **Settings and Privacy > Security and Account Access > Security**.
2. Open **Two-Step Verification > Authentication App**.
3. Turn Authentication App off, then turn it on again.
4. X shows a QR code. Then choose **Can't scan the QR code?** to reveal the text secret.
5. Copy the long secret key. Then store it in a password manager before leaving the setup screen.
6. Add that key to your authenticator app if you are setting it up fresh.
7. Finish enabling 2FA on X by entering the current 6-digit code. The code comes from your authenticator app.
8. Send the new long key in `totp_secret` when you call Xquik.

<Warning>

Finish the X-side 2FA confirmation after copying the secret key. If you abandon setup before confirmation, re-authentication cannot use that key.

</Warning>

<Note>

See [2FA secret key setup](/api-reference/x-accounts/connect#2fa-secret-key-setup) for the full connection checklist.

</Note>

## Response

### 200 OK

| Field       | Type     | Description                                                                                                                                                                                                |
| ----------- | -------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `id`        | `string` | Account ID.                                                                                                                                                                                                |
| `xUsername` | `string` | X username.                                                                                                                                                                                                |
| `xUserId`   | `string` | X user ID.                                                                                                                                                                                                 |
| `status`    | `string` | Account status (for example `active`).                                                                                                                                                                     |
| `health`    | `string` | Derived login and cookie health. One of `healthy`, `locked`, `needsReauth`, `recovering`, `suspended`, `temporaryIssue`. See [Account health](/api-reference/x-accounts/list#account-health) for meanings. |
| `createdAt` | `string` | ISO 8601 creation timestamp.                                                                                                                                                                               |

```json
{
  "id": "3",
  "xUsername": "elonmusk",
  "xUserId": "44196397",
  "status": "active",
  "health": "healthy",
  "createdAt": "2026-02-20T08:15:00.000Z"
}
```

### 400 Invalid input

`{ "error": "invalid_input", "message": "Missing required password field" }`

{"\n"}

Missing `password` field or invalid format.

{"\n"}

`{ "error": "invalid_id", "message": "Invalid account ID format" }`

{"\n"}

The provided account ID is not a valid format.

### 401 Unauthenticated

`{ "error": "unauthenticated", "message": "Missing or invalid API key" }`

{"\n"}

Missing or invalid API key.

### 202 Sign-in continues

A key's sign-in past 75 seconds answers `pending` with a `Location` status URL. Wait for `Retry-After`, then call [Get X Account Connection Status](/api-reference/x-accounts/connection-attempt). X may also ask for an email code, which answers `requires_email_code`. Send it to [Submit Email Code](/api-reference/x-accounts/submit-challenge).

### 404 Not found

No account exists with this ID, or it belongs to a different Xquik account.

### 409 Another X account

`{ "error": "x_account_mismatch", "message": "This sign-in belongs to a different X account. Connect it as a new account instead." }`

{"\n"}

The stored login stays as it was.

### 429 Login cooldown

`{ "error": "login_cooldown", "message": "Login is temporarily paused", "reason": "automated", "retryAfterMs": 3600000 }`

{"\n"}

A prior login attempt triggered a cooldown (for example, X flagged the session). Wait for `retryAfterMs` before retrying. The response includes a `Retry-After` header in seconds.

### 429 Rate limited

`{ "error": "rate_limit_exceeded", "message": "Connection safety limit reached. Try again later.", "retryAfter": 900 }`

{"\n"}

You sent too many failed logins in 15 minutes. The limit counts this caller or this X account. Wait the `Retry-After` seconds, then try once. Each account a caller connects raises its limit. See the [rate limits guide](/guides/rate-limits) for details.

### 422 Login failed

X rejected the submitted password or TOTP secret. Retry with the current password and the saved Authenticator App secret key. Use the key, not a 6-digit code.

{"\n"}

`{ "error": "passkey_required", "message": "X asked this account to sign in with a passkey. Delete the passkey in X's security settings, keep Authentication app 2FA, then try again." }`

{"\n"}

X showed this account a passkey sign-in, which Xquik can't complete. Open X **Settings and Privacy > Security and Account Access > Security > Passkey**. Delete the passkey but keep Authenticator App 2FA on, then re-authenticate.

### 503 Service unavailable

`{ "error": "service_unavailable", "message": "Service temporarily unavailable. Try again." }`

{"\n"}

The X re-authentication service is temporarily unavailable. Retry after a short delay.
