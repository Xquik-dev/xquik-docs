Change a post monitor's label, event types or active state. The tracked post
stays the same, so the monitor ID & its history stay usable.

<Callout icon="circle-check" color="#16a34a">

**Free.** This endpoint does not consume credits. Active monitors bill 30 credits per hour.

</Callout>

<CodeGroup>

```bash cURL
curl -X PATCH https://xquik.com/api/v1/monitors/posts/31 \
  -H "x-api-key: xq_YOUR_KEY_HERE" \
  -H "Content-Type: application/json" \
  -d '{
    "eventTypes": ["post.reply.new", "post.likes.changed"],
    "isActive": true
  }' |
  jq -c '{
    post_monitor_id: .id,
    event_types: .eventTypes,
    is_active: .isActive,
    next_billing_at: .nextBillingAt
  }'
```

```javascript Node.js
const monitorId = "31";
const response = await fetch(`https://xquik.com/api/v1/monitors/posts/${monitorId}`, {
  method: "PATCH",
  headers: {
    "x-api-key": "xq_YOUR_KEY_HERE",
    "Content-Type": "application/json",
  },
  body: JSON.stringify({
    eventTypes: ["post.reply.new", "post.likes.changed"],
    isActive: true,
  }),
});
const monitor = await response.json();
const state = {
  post_monitor_id: monitor.id,
  event_types: monitor.eventTypes,
  is_active: monitor.isActive,
  next_billing_at: monitor.nextBillingAt,
};
process.stdout.write(`${JSON.stringify(state)}\n`);
```

## Pause & resume a post monitor

Send `isActive: false` to stop reads, events & hourly billing. The monitor &
its history stay.

Send `isActive: true` to resume. Xquik reads the post first. While X hides the
post, the route answers `409` & changes nothing. The monitor stays paused &
costs nothing.

A resumed monitor reports nothing from its pause. Its first read sets the new
starting point.

To track a different post, create a new monitor. Then delete or pause the old
one.

## Path parameters

<ParamField path="id" type="string" required>

The post monitor ID.

</ParamField>

## Headers

<ParamField header="x-api-key" type="string" required>

Your API key. Session cookie authentication is also supported. Generate a key from the [dashboard](https://dashboard.xquik.com/en/account?tab=api-keys).

</ParamField>

<ParamField header="Content-Type" type="string" required>

Must be `application/json`.

</ParamField>

## Body

Send at least 1 field.

<ParamField body="eventTypes" type="string[]">

Post event types to send, 1 to 10. Replaces the current list. Valid types are
`post.reply.new`, `post.quote.new`, `post.likes.changed`,
`post.retweets.changed`, `post.replies.changed`, `post.quotes.changed`,
`post.bookmarks.changed`, `post.views.changed`, `post.edited` &
`post.deleted`.

</ParamField>

<ParamField body="name" type="string | null">

New label, 1 to 80 characters. Send `null` to remove it.

</ParamField>

<ParamField body="isActive" type="boolean">

`false` pauses the monitor. `true` resumes it once X shows the post.

</ParamField>

## Response

### 200 OK

Returns the updated monitor, shaped like the
[Get Post Monitor](/api-reference/monitors/get-post) response.

<ResponseField name="id" type="string">
  Unique post monitor ID.
</ResponseField>
<ResponseField name="eventTypes" type="string[]">
  Post event types this monitor sends.
</ResponseField>
<ResponseField name="isActive" type="boolean">
  Whether the monitor is active.
</ResponseField>
<ResponseField name="nextBillingAt" type="string">
  Next hourly credit charge time.
</ResponseField>
<ResponseField name="metrics" type="object">
  The 6 metrics, each with `current` & `gain` since tracking began.
</ResponseField>

### 400 Invalid input

No field to change, or a field is invalid. The message says what to fix.

### 401 Unauthenticated

Missing or invalid API key.

### 404 Not found

No post monitor has this ID on your account.

### 409 Post unavailable

X still hides the post, so the monitor stays paused. `reason` is `deleted`,
`protected` or `author_suspended` when X names it.

### 429 Rate limited

Too many requests. Wait for the `Retry-After` header before retrying.

### 502 X unavailable

X failed the read while resuming. Retry after a short wait.

### 503 Busy

Xquik is busy right now. Wait for `Retry-After`, then retry.
