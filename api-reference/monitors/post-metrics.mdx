Read a monitored post's metrics hour by hour. Each bucket holds every metric's
value at the hour's end & its gain over that hour.

<Callout icon="circle-check" color="#16a34a">

**Free.** This endpoint does not consume credits.

</Callout>

<CodeGroup>

```bash cURL
curl "https://xquik.com/api/v1/monitors/posts/31/metrics?hours=24" \
  -H "x-api-key: xq_YOUR_KEY_HERE" |
  jq -c '.buckets[] | {
    hour: .at,
    views: .metrics.views.value,
    view_gain: .metrics.views.gain,
    likes: .metrics.likes.value,
    like_gain: .metrics.likes.gain
  }'
```

```javascript Node.js
const monitorId = "31";
const response = await fetch(
  `https://xquik.com/api/v1/monitors/posts/${monitorId}/metrics?hours=24`,
  { headers: { "x-api-key": "xq_YOUR_KEY_HERE" } },
);
const history = await response.json();
for (const bucket of history.buckets) {
  const row = {
    hour: bucket.at,
    views: bucket.metrics.views.value,
    view_gain: bucket.metrics.views.gain,
    likes: bucket.metrics.likes.value,
    like_gain: bucket.metrics.likes.gain,
  };
  process.stdout.write(`${JSON.stringify(row)}\n`);
}
```

```python Python
import json
import requests

monitor_id = "31"
response = requests.get(
    f"https://xquik.com/api/v1/monitors/posts/{monitor_id}/metrics",
    headers={"x-api-key": "xq_YOUR_KEY_HERE"},
    params={"hours": 24},
)
history = response.json()
for bucket in history["buckets"]:
    row = {
        "hour": bucket["at"],
        "views": bucket["metrics"]["views"]["value"],
        "view_gain": bucket["metrics"]["views"]["gain"],
        "likes": bucket["metrics"]["likes"]["value"],
        "like_gain": bucket["metrics"]["likes"]["gain"],
    }
    print(json.dumps(row))
```

## How do I chart a tweet's engagement over time?

Buckets come oldest first, 1 per hour. The last bucket is the current hour, so
its values keep moving.

Hours before tracking began carry the starting values with a gain of `0`.
Xquik keeps 30 days of history, which matches the 720-hour limit.

Sum the gains for a period's total. Use the last bucket's value for the current
count. A value & its gain are `null` when X shows no count, as for views on
old posts.

## Path parameters

<ParamField path="id" type="string" required>

The post monitor ID.

</ParamField>

## Query parameters

<ParamField query="hours" type="integer">

Hours to return, from 1 to 720. Default `12`.

</ParamField>

## Headers

<ParamField header="x-api-key" type="string" required>

Your API key. Session cookie authentication is also supported. Generate a key from the [dashboard](https://dashboard.xquik.com/en/account?tab=api-keys).

</ParamField>

## Response

### 200 OK

<ResponseField name="hours" type="integer">
  Number of hours returned.
</ResponseField>
<ResponseField name="buckets" type="object[]">
  Hourly buckets, oldest first.
</ResponseField>
<ResponseField name="buckets[].at" type="string">
  ISO 8601 start of the hour.
</ResponseField>
<ResponseField name="buckets[].metrics" type="object">
  `views`, `likes`, `retweets`, `replies`, `quotes` & `bookmarks`. Each holds `value` at the hour's
  end & `gain` over that hour.
</ResponseField>

### 400 Invalid input

`hours` is not a whole number from 1 to 720.

### 401 Unauthenticated

Missing or invalid API key.

### 404 Not found

No post monitor has this ID on your account.

### 429 Rate limited

Too many requests. Wait for the `Retry-After` header before retrying.
