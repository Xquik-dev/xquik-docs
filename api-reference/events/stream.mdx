## How the stream works

- Each event arrives as a server-sent event. `event` is its type, and `id` is its
  event ID. `data` is the event object [List events](/api-reference/events/list)
  returns.
- A new connection gets each event stored after it opens.
- To catch up after a drop, reconnect with `Last-Event-ID`. The stream first
  sends every event after that ID, oldest first. It then sends the new ones.
- Events expire 30 days after Xquik creates them. So a replay reaches back 30
  days at most. An ID Xquik no longer keeps replays every event it still keeps.
- The first frame is `retry: 3000`, so a client waits 3 s before it reconnects.
- An idle stream sends a `: keep-alive` comment every 15 s.
- A connection ends after 30 minutes. Reconnect with the last ID you got.
  SSE libraries do this for you.
- Keep up to 200 streams open per account. Xquik may answer `429` with
  `too_many_streams` to a 201st.

<CodeGroup>

```bash cURL
curl -N "https://xquik.com/api/v1/events/stream" \
  -H "x-api-key: xq_YOUR_KEY_HERE" \
  -H "Last-Event-ID: 42"
```

```javascript Node.js
let lastEventId;

async function readStream() {
  const response = await fetch("https://xquik.com/api/v1/events/stream", {
    headers: {
      "x-api-key": "xq_YOUR_KEY_HERE",
      ...(lastEventId === undefined ? {} : { "Last-Event-ID": lastEventId }),
    },
  });
  if (!response.ok) throw new Error(`Stream refused: ${response.status}`);
  const decoder = new TextDecoder();
  let buffer = "";
  for await (const chunk of response.body) {
    buffer += decoder.decode(chunk, { stream: true });
    const frames = buffer.split("\n\n");
    buffer = frames.pop() ?? "";
    for (const frame of frames) {
      const fields = Object.fromEntries(
        frame
          .split("\n")
          .filter((line) => line !== "" && !line.startsWith(":"))
          .map((line) => [line.slice(0, line.indexOf(":")), line.slice(line.indexOf(":") + 2)]),
      );
      if (fields.data === undefined) continue;
      lastEventId = fields.id;
      const event = JSON.parse(fields.data);
      process.stdout.write(`${JSON.stringify({ id: event.id, type: event.type })}\n`);
    }
  }
}

// The stream ends after 30 minutes. Reconnect with the last ID.
for (;;) {
  await readStream().catch((error) => console.error(error.message));
  await new Promise((resolve) => setTimeout(resolve, 3000));
}
```

```python Python
import json
import time

import requests

last_event_id = None

def read_stream():
    global last_event_id
    headers = {"x-api-key": "xq_YOUR_KEY_HERE"}
    if last_event_id is not None:
        headers["Last-Event-ID"] = last_event_id
    with requests.get(
        "https://xquik.com/api/v1/events/stream",
        headers=headers,
        stream=True,
        timeout=(10, 60),
    ) as response:
        response.raise_for_status()
        fields = {}
        for line in response.iter_lines(decode_unicode=True):
            if line == "":
                if "data" in fields:
                    last_event_id = fields.get("id")
                    event = json.loads(fields["data"])
                    print(json.dumps({"id": event["id"], "type": event["type"]}))
                fields = {}
            elif not line.startswith(":"):
                name, _, value = line.partition(": ")
                fields[name] = value

# The stream ends after 30 minutes. Reconnect with the last ID.
while True:
    try:
        read_stream()
    except requests.RequestException as error:
        print(error)
    time.sleep(3)
```

</CodeGroup>

These examples print 1 line per event. They keep the last event ID for the next connection.
Store that ID if your process restarts.
With it, the first connection after a restart replays what it missed.

## Headers

| Header          | Type     | Required | Description                                                                                                                             |
| --------------- | -------- | -------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| `x-api-key`     | `string` | Yes      | Your API key.                                                                                                                           |
| `Last-Event-ID` | `string` | No       | The last event ID your client got. The stream first sends every event after it. SSE libraries send it on their own when they reconnect. |

</section>

<section>

## Query parameters

| Query parameter | Type      | Required | Description                                                                                                                                                                                                                                         |
| --------------- | --------- | -------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `include`       | `string`  | No       | Set to `post_metrics` to also get each post monitor's saved numbers as they change. Any other value is refused.                                                                                                                                     |
| `lookBack`      | `boolean` | No       | Set to `true` to resume 30 seconds before `Last-Event-ID`. Events saved late then still arrive. Events you already have can arrive again, so skip IDs you've seen. An ID the stream can't find starts 5 minutes back, not 30 days. Default `false`. |

</section>

## Response

### 200 OK

```text
retry: 3000

id: 42
event: tweet.new
data: {"id":"42","type":"tweet.new","monitorId":"7","monitorType":"account","occurredAt":"2025-01-15T12:00:00.000Z","data":{}}

: keep-alive
```

A `text/event-stream` body. Each event's `data` line holds the event object that
[List events](/api-reference/events/list) documents. It is 1 line of JSON.

### 401 Unauthenticated

Missing or invalid API key. Check the `x-api-key` header value.

### 429 Too many streams or requests

`too_many_streams` means the account has 200 streams open. Close 1, then
connect again. `rate_limit_exceeded` means too many requests. Wait for the
`Retry-After` header before you retry.
