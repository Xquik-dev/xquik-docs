Search Tweets accepts keywords, hashtags,
operators, dates, authors, media, and engagement filters. For exact lookup,
send a Tweet ID or X status URL in `q`. Send it with no time params. To
search one user's tweets as a plain timeline, call
[Search user tweets](/api-reference/x/user-tweets)
(`GET /x/users/{id}/tweets`). Date params limit results to that window, as in
`q=from:username&sinceTime=2026-05-01&untilTime=2026-05-02`.
Cursor requests return an empty final page for exact IDs.

```bash cURL
curl -G https://xquik.com/api/v1/x/tweets/search \
  --data-urlencode "q=giveaway" \
  --data-urlencode "fromUser=username" \
  --data-urlencode "mediaType=media" \
  --data-urlencode "verifiedOnly=true" \
  --data-urlencode "queryType=Latest" \
  -H "x-api-key: xq_your_api_key_here" | tee page-1.json | jq

# Page 2 - pass next_cursor from the previous response
CURSOR=$(jq -r .next_cursor page-1.json)
curl -G https://xquik.com/api/v1/x/tweets/search \
  --data-urlencode "q=giveaway" \
  --data-urlencode "fromUser=username" \
  --data-urlencode "mediaType=media" \
  --data-urlencode "cursor=$CURSOR" \
  -H "x-api-key: xq_your_api_key_here" | jq
```

```javascript Node.js
const params = new URLSearchParams({
  q: "giveaway",
  fromUser: "username",
  mediaType: "media",
});
const response = await fetch(`https://xquik.com/api/v1/x/tweets/search?${params}`, {
  headers: { "x-api-key": "xq_your_api_key_here" },
});
const firstPage = await response.json();
if (!response.ok) throw new Error(JSON.stringify(firstPage));

let page = firstPage;
let pageCursor = "";
const seenCursors = new Set();
for (let pageIndex = 0; pageIndex < 3; pageIndex += 1) {
  const searchRows = page.tweets.map((tweet) => ({
    tweet_id: tweet.id,
    text: tweet.text,
    author_id: tweet.author?.id ?? null,
    author_username: tweet.author?.username ?? null,
    author_name: tweet.author?.name ?? null,
    author_followers: tweet.author?.followers ?? null,
    author_verified: tweet.author?.verified ?? null,
    author_profile_picture: tweet.author?.profilePicture ?? null,
    created_at: tweet.createdAt ?? null,
    like_count: tweet.likeCount ?? null,
    reply_count: tweet.replyCount ?? null,
    retweet_count: tweet.retweetCount ?? null,
    quote_count: tweet.quoteCount ?? null,
    view_count: tweet.viewCount ?? null,
    media_urls: (tweet.media ?? []).map((item) => item.mediaUrl).filter(Boolean),
    query: params.get("q"),
    page_index: pageIndex,
    page_cursor: pageCursor,
    next_cursor: page.next_cursor,
    has_next_page: page.has_next_page,
  }));
  for (const row of searchRows) process.stdout.write(`${JSON.stringify(row)}\n`);

  if (!page.has_next_page || page.next_cursor === "") break;
  if (page.next_cursor === pageCursor || seenCursors.has(page.next_cursor)) {
    throw new Error("pagination cursor repeated");
  }

  seenCursors.add(page.next_cursor);
  pageCursor = page.next_cursor;
  const nextParams = new URLSearchParams(params);
  nextParams.set("cursor", pageCursor);
  const nextResponse = await fetch(`https://xquik.com/api/v1/x/tweets/search?${nextParams}`, {
    headers: { "x-api-key": "xq_your_api_key_here" },
  });
  page = await nextResponse.json();
  if (!nextResponse.ok) throw new Error(JSON.stringify(page));
}
```

## Direct API handoff

Use `GET /x/tweets/search` for live JSON. Store IDs and `next_cursor` to resume.
Use [`tweet_search_extractor`](/guides/tweet-scraper-csv-export) for estimates,
saved pages, or downloadable CSV, JSON, and XLSX files.

{"\n"}

`limit` bounds unique matching tweets after filtering. Keep `q`, filters,
`queryType`, and `limit` unchanged when resuming with `cursor=next_cursor`.
Continue while `has_next_page` is true. Deduplicate IDs and reject repeated cursors.
Explicit `mode=coverage` returns retained rows when its request window expires.
Check `diagnostic.deadlineReached` and `diagnostic.complete`. Partial coverage does not mean the source ran out of tweets.

{"\n"}

For account date windows, `sinceTime` and `untilTime` limit results to that
window. Inline `since_time:` and `until_time:` intersect. The start is inclusive. The end is exclusive. Days are UTC.
`q=from:username&sinceTime=2026-05-01&untilTime=2026-05-02` behaves like
`from:username since:2026-05-01 until:2026-05-02`. Use `queryType=Latest` for
backfills or keywords for ranked search. Bounds apply to every returned page.
Coverage continues past rejected rows.

{"\n"}

`-filter:nativeretweets` drops button reposts but keeps quotes & manual RT
text. `include:nativeretweets` adds button reposts to author searches.
`-filter:retweets` also drops manual RT text. Xquik keeps the operator you send.

{"\n"}

Account searches return all of the account's posts & reposts in the window.
Continue when the response includes `next_cursor`.
`mode=standard` keeps the legacy behavior for old integrations.

{"\n"}

A search that needs a protected author returns `403` with
`x_account_protected` and no charge. Choose a public account. Searches across
several authors are unaffected.

## Keep only posts about a topic

A word like rust or jaguar matches many meanings. Send `topic` to name the one you want.
AI-powered analysis asks `Is this post about <topic>?` of each post the search reads.
Posts scoring 0.5 or more come back, each with its `topicScore`.
The check reads the post text & photos X doesn't mark sensitive.

```bash
curl -G "https://xquik.com/api/v1/x/tweets/search" \
  -H "x-api-key: $XQUIK_API_KEY" \
  --data-urlencode "q=rust lang:en -filter:replies" \
  --data-urlencode "topic=the Rust programming language" \
  --data-urlencode "limit=30"
```

```json
{
  "tweets": [
    {
      "id": "2118059163251323266",
      "text": "Rust is just a cool language",
      "topicScore": 0.91
    }
  ],
  "has_next_page": true,
  "next_cursor": "DAADDAABCgABF...",
  "topicFilter": {
    "topic": "the Rust programming language",
    "question": "Is this post about the Rust programming language?",
    "cutoff": 0.5,
    "checked": 30,
    "kept": 14,
    "unchecked": []
  }
}
```

- Each kept post costs 2 credits, the AI analysis price, instead of 1. A post the filter drops costs nothing.
- `limit` counts checked posts. Only kept posts come back.
- `unchecked` lists posts the check couldn't answer. They cost nothing & stay out.
- Follow `next_cursor` with the same `topic` to check the next posts.

## Matched text ranges

Each row says where its `text` matches the search, in `textHighlights`. Use the
ranges to bold the matched words or cut a snippet around them.

- `startIndex` is the first code point of a match. `endIndex` is the first one after it.
- Offsets count code points of the row's `text`, as `displayTextRange` does.
- JavaScript counts some characters, such as most emoji, as 2 units. Split the text by code point first.
- The list is empty when X marks nothing. One case is a `from:` search without words.
- X marks matches only in a post's first 280 characters. Later matches in a long post get no range.

```javascript
const characters = [...tweet.text];
const matches = tweet.textHighlights.map(({ startIndex, endIndex }) =>
  characters.slice(startIndex, endIndex).join(""),
);
```

## Query parameters

| Query parameter | Type      | Required | Description                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| --------------- | --------- | -------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `q`             | `string`  | Yes      | Send the caller's query, Tweet ID, or status URL. `query` is an alias. Quotes match phrases. Hyphens negate terms. Use `exactPhrase` for literals. X (Twitter) searches up to 512 characters. A longer query can answer 424.                                                                                                                                                                                                                                                                                                                    |
| `queryType`     | `string`  | No       | `Latest` lists posts newest first. `Top` ranks posts by engagement within each page. A later page can hold a higher ranked post. Use `Latest` for posts in time order. Any case works. `result_type` and `sort_order` are accepted aliases, as are `type`, `search_type`, `product`, `category` & `section`. `recency` maps to `Latest`. `relevancy` maps to `Top`. `Photos`, `Videos` & `Media` return posts with that media type, unless you set `mediaType`. `People` & `Lists` answer 400 & point to `/x/users/search` & `/x/lists/search`. |
| `mode`          | `string`  | No       | Optional compatibility override. Omit it to get the fullest results. `standard` keeps the legacy pagination. Use `coverage` for a one-shot diagnostic response without cursor pagination.                                                                                                                                                                                                                                                                                                                                                       |
| `cursor`        | `string`  | No       | Pass `next_cursor` back unchanged. New Xquik cursors resume automatic coverage. Existing unprefixed cursors keep legacy behavior.                                                                                                                                                                                                                                                                                                                                                                                                               |
| `sinceTime`     | `string`  | No       | Inclusive lower bound. Intersects with inline bounds.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| `untilTime`     | `string`  | No       | Exclusive upper bound. Intersects with inline bounds.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| `limit`         | `integer` | No       | Maximum Tweets per automatic page, from `1` through `10000`. `count` and `max_results` are accepted aliases. So are `pageSize`, `maxItems`, `max_items` & `per_page`. Keep the value on cursor requests.                                                                                                                                                                                                                                                                                                                                        |

### 400 Missing query

The `q` query parameter is empty or missing.

### 401 Unauthenticated

Anonymous requests get `WWW-Authenticate: Bearer` and a guest wallet checkout action. This is not a Payment challenge.

{"\n"}

Missing or invalid API key. Check the `x-api-key` header value.

### 402 Payment required

Account keys get account options. Guest keys get guest top-up only.
No checkout starts automatically. Confirm any payment action.

### 404 Missing user or tweet

`user_not_found` means a required user lookup failed. Check the username.
`tweet_not_found` means an exact tweet lookup failed. Check the tweet ID or URL.
Neither means a search completed with no matching tweets.

### 502 X API unavailable

The read service returned an error. Retry after a short delay.

### 429 Rate limit exceeded

You exceeded your tier rate limit. Wait for the `Retry-After` header before retrying.

### 424 Search unavailable

`{ "error": "search_unavailable" }`

{"\n"}

X fails this query on every read, so a retry fails too. Follow its message to
fix the search. The normalized v1 contract also returns 424 `x_api_unavailable`.
