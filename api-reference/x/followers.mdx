Get followers returns follower profiles for one X account. Name the account by username or numeric user ID. The endpoint is `GET /api/v1/x/users/{id}/followers`.

```bash cURL
# Username follower page
curl "https://xquik.com/api/v1/x/users/username/followers?pageSize=200" \
  -H "x-api-key: xq_your_api_key_here" | jq

# Numeric user ID follower page

# Resume with next_cursor from the previous page
curl -G "https://xquik.com/api/v1/x/users/username/followers" \
  --data-urlencode "cursor=DAACCgACGE..." \
  --data-urlencode "pageSize=200" \
  -H "x-api-key: xq_your_api_key_here" | jq
```

```javascript Node.js
const userIdOrUsername = "username";
let pageCursor = "";
const seenCursors = new Set();

for (let pageIndex = 0; pageIndex < 3; pageIndex += 1) {
  const params = new URLSearchParams({ pageSize: "200" });
  if (pageCursor !== "") params.set("cursor", pageCursor);

  const response = await fetch(
    `https://xquik.com/api/v1/x/users/${userIdOrUsername}/followers?${params}`,
    { headers: { "x-api-key": "xq_your_api_key_here" } },
  );
  const page = await response.json();
  if (!response.ok) throw new Error(JSON.stringify(page));

  const importRows = page.users.map((user) => ({
    source_user_id_or_username: userIdOrUsername,
    x_user_id: user.id,
    x_username: user.username,
    display_name: user.name,
    description: user.description ?? null,
    location: user.location ?? null,
    website_url: user.url ?? null,
    follower_count: user.followers ?? null,
    following_count: user.following ?? null,
    verified: user.verified ?? false,
    verified_type: user.verifiedType ?? null,
    profile_picture_url: user.profilePicture ?? null,
    cover_picture_url: user.coverPicture ?? null,
    account_created_at: user.createdAt ?? null,
    statuses_count: user.statusesCount ?? null,
    page_index: pageIndex,
    page_cursor: pageCursor,
    next_cursor: page.next_cursor,
    has_next_page: page.has_next_page,
  }));
  for (const row of importRows) process.stdout.write(`${JSON.stringify(row)}\n`);

  if (!page.has_next_page || page.next_cursor === "") break;
  if (page.next_cursor === pageCursor || seenCursors.has(page.next_cursor)) {
    throw new Error("pagination cursor repeated");
  }
  seenCursors.add(page.next_cursor);
  pageCursor = page.next_cursor;
}
```

```python Python
import json
import requests

user_id_or_username = "44196397"
page_cursor = ""
seen_cursors = set()

for page_index in range(3):
    params = {"pageSize": "200"}
    if page_cursor:
        params["cursor"] = page_cursor

    response = requests.get(
        f"https://xquik.com/api/v1/x/users/{user_id_or_username}/followers",
        params=params,
        headers={"x-api-key": "xq_your_api_key_here"},
    )
    page = response.json()
    if not response.ok:
        raise RuntimeError(page)

    for user in page["users"]:
        import_row = {
            "source_user_id_or_username": user_id_or_username,
            "x_user_id": user["id"],
            "x_username": user["username"],
            "display_name": user["name"],
            "description": user.get("description"),
            "location": user.get("location"),
            "website_url": user.get("url"),
            "follower_count": user.get("followers"),
            "following_count": user.get("following"),
            "verified": user.get("verified", False),
            "verified_type": user.get("verifiedType"),
            "profile_picture_url": user.get("profilePicture"),
            "cover_picture_url": user.get("coverPicture"),
            "account_created_at": user.get("createdAt"),
            "statuses_count": user.get("statusesCount"),
            "page_index": page_index,
            "page_cursor": page_cursor,
            "next_cursor": page["next_cursor"],
            "has_next_page": page["has_next_page"],
        }
        print(json.dumps(import_row, separators=(",", ":")))

    if not page["has_next_page"] or not page["next_cursor"]:
        break
    if page["next_cursor"] == page_cursor or page["next_cursor"] in seen_cursors:
        raise RuntimeError("pagination cursor repeated")
    seen_cursors.add(page["next_cursor"])
    page_cursor = page["next_cursor"]
```

The Node.js and Python snippets write JSON Lines import rows, not raw
follower pages. Store each mapped row and the latest `next_cursor` in your
sync job. It can then resume from the last completed page.

## Direct follower handoff

Use `GET /api/v1/x/users/{id}/followers` when a CRM, warehouse, audience, or
agent workflow needs follower rows. It returns them for one profile now. The
examples above write JSON Lines rows for imports or upserts. Each row is keyed
by `x_user_id` and holds its page's cursor state.

{"\n"}

Followers come newest first.

</section>

<section>

## Choose live API or saved export

Use this endpoint for current JSON pages in an app, queue, or agent. It fits when
the caller can store `next_cursor` and process `users[]` immediately. Use
[`follower_explorer`](/guides/follower-export-crm) for a
cost estimate, reusable extraction ID, stored result pages, or files. Its files
are CSV, JSON, or XLSX, ready after completion.

{"\n"}

Automatic `pageSize` accepts 20 to 10,000. Standard mode accepts 20 to 200.
Paid calls can return fewer rows. `users.length` is the billable row count.
Zero affordable results return
`402 insufficient_credits`.

{"\n"}

For high-volume follower pulls, deduplicate profiles by `id`. Continue through empty pages while the cursor advances. Stop with a partial-result status when `next_cursor` is missing or repeats.

</section>

## Build a Twitter follower tracker

An [account monitor](/api-reference/monitors/create) tracks followers for you,
with no snapshot diff. Select `follower.added` and `follower.removed`. Each
event holds the follower's profile, or its ID when X shows none. New followers
usually arrive within a minute. Losses take about 15 minutes, or up to 2 hours
above 5,000 followers.

{"\n"}

- `follower.added` holds `followedAt`, X's time of the follow when X gives one.
- `follower.removed` holds `reason` when the cause is known. `unfollowed` means
  the follow ended.
  `unavailable` means X shows no account for it, as after a suspension.
- `followKind` marks a returning follower as `refollow` or `return`.
- `profile.followers.changed` reports follower count moves, at most once a minute.

{"\n"}

Monitors name every lost follower for accounts with up to 100,000 followers.
Above that, they name losses among the newest 5,000. An active monitor costs 30
credits per hour. Use this endpoint once for the
starting list. Key its rows by `users[].id`, since usernames change. To track
without code, open the
[Twitter unfollowers tracker](https://xquik.com/en/twitter-unfollowers-tracker).

</section>

## Which follower endpoint?

- Use `GET /api/v1/x/users/{id}/followers` for one account's live follower page.
- Use [`follower_explorer`](/guides/follower-export-crm) when you need a saved job, CSV, JSON, or XLSX export.
- Use `GET /api/v1/x/users/{id}/following` for accounts the user follows.
- Use `GET /api/v1/x/users/{id}/verified-followers` when you only need verified followers.
- Use [Followers You Know](/api-reference/x/followers-you-know) for followers you share with another account.
- Use an [account monitor](/api-reference/monitors/create) for each new or lost follower.

</section>

## Query parameters

| Query parameter  | Type      | Required | Description                                                                                                                                                                                                                    |
| ---------------- | --------- | -------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `cursor`         | `string`  | No       | Pass `next_cursor` back unchanged. New Xquik cursors resume automatic coverage. Existing unprefixed cursors keep legacy behavior.                                                                                              |
| `mode`           | `string`  | No       | Optional compatibility override. Omit it to get the fullest list. `standard` keeps the legacy pagination. Use `coverage` for a one-shot diagnostic response without cursor pagination.                                         |
| `after`          | `string`  | No       | Legacy cursor alias for `cursor`. When both are present, `cursor` wins.                                                                                                                                                        |
| `pageSize`       | `number`  | No       | Automatic pages accept `20` through `10000`. Standard pages accept `20` through `200`. The default is `200`. Credits can reduce the returned row count.                                                                        |
| `limit`          | `number`  | No       | With `mode=coverage`, set a one-shot cap from `1` through `10000`. Otherwise, this is a legacy page size alias. `pageSize` wins.                                                                                               |
| `enrichProfiles` | `boolean` | No       | Set `true` to add each row's full profile, as `GET /x/users/{id}` returns it. Pages take several seconds longer. The price per row stays the same. Later pages can leave it out, & `next_cursor` still works. Default `false`. |

### User result filters

These filters apply before billing. Selective filters can return fewer rows.

<UserResultFilterParams />

| Query parameter | Type      | Required | Description                                                                                                                                                                                                                                                                                                                                                                                               |
| --------------- | --------- | -------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `maxScan`       | `integer` | No       | Most profiles 1 request reads, kept or dropped by the filters. The answer then holds the kept profiles, the dropped count & the next cursor. Each request may send its own value. Without it, a filtered read scans at most 100,000 profiles of the list. The limit spans all pages of the read. The page that reaches the limit ends the list & names `scanLimit`. An unfiltered read has no scan limit. |

### 400 Invalid user ID

`{ "error": "invalid_user_id", "message": "Send a user ID, @username or profile URL, such as x.com/nasa." }`

### 401 Unauthenticated

Anonymous requests get `WWW-Authenticate: Bearer` and a guest wallet checkout action. This is not a Payment challenge.

### 402 Payment required

Account keys get account options. Guest keys get guest top-up only.
No checkout starts automatically. Confirm any payment action.

### 502 X API unavailable

The read service returned an error. Retry after a short delay.

### 429 Rate limit exceeded

You exceeded your tier rate limit. Wait for the `Retry-After` header before retrying.

### 424 Dependency failed

The normalized v1 response contract can return 424 when the read service is unavailable.
