## The same search on another path

`GET /x/communities/tweets` searches the tweets in one Community, or across every
Community without `communityId`, exactly as
[Community search](/api-reference/x/community-search) does on `GET /x/communities/search`. Both take the same
`communityId`, `q`, `queryType`, `cursor`, and `pageSize`, and answer the same page of tweets.

Keep this path when your integration already uses it. New integrations can use either.

To get a Community's posts for a hashtag, search it with `q=#tag`, such as
`q=#bitcoin`, and the Community's `communityId`.

## Query parameters

<ParamField query="communityId" type="string">

Numeric ID of the Community whose tweets you want to search. Leave it out to
search every Community.

</ParamField>

<ParamField query="q" type="string" required>

Search query for the Community's tweets.

</ParamField>

<ParamField query="queryType" type="string">

Sort order. `Top` returns the most relevant tweets, `Latest` the most recent. Defaults to `Latest`.

</ParamField>

<ParamField query="cursor" type="string">

Pagination cursor from a previous response. Omit for the first page.

</ParamField>

<ParamField query="pageSize" type="number">

Upper bound for tweets per page. Range: 1-100. Default: `20`.

</ParamField>
