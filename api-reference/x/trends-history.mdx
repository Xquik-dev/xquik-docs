```javascript Node.js
const params = new URLSearchParams({
  country: "TR",
  from: "2026-10-13",
  to: "2026-10-14",
  every: "1h",
});
const response = await fetch(`https://xquik.com/api/v1/x/trends/history?${params}`, {
  headers: { "x-api-key": "xq_your_api_key_here" },
});
const data = await response.json();
const trendRows = data.snapshots.flatMap((snapshot) =>
  snapshot.trends.map((trend) => ({
    captured_at: snapshot.capturedAt,
    region_woeid: data.woeid,
    rank: trend.rank,
    trend_name: trend.name,
    tweet_volume: trend.tweetVolume ?? null,
  })),
);

for (const row of trendRows) {
  process.stdout.write(`${JSON.stringify(row)}\n`);
}
```

</CodeGroup>

Use `GET /x/trends/history` to read the Twitter trends archive of a place.
It answers what was trending on Twitter yesterday or last week. It covers any day since 2026-10-13.
Xquik stores 1 list per place every 5 minutes. It keeps each list for 25 months.
The archive starts 2026-10-13 02:20 UTC. Earlier trends are not available.
Each returned list costs 1 credit, so 24 lists cost 24 credits.
A step with no stored list returns nothing and costs nothing.

## Read Twitter trends history by date

Pick the place by `country`, `location`, or `woeid`. Without one, trends are worldwide.
Set the range with `from` and `to`, and the step with `every`.
`from` and `to` take a time or span back from now, such as `7d`. A schedule can then read the last day on every run.
The answer names the range it read in `fromTime` and `toTime`.
Each step returns the first list Xquik stored in it, oldest first.
Every list carries `capturedAt`, the time Xquik read it from X. Xquik never estimates that time.

A request returns 24 lists, or up to 100 with `limit`.
A wider range answers `has_next_page` as `true`. Send `next_cursor` as `cursor` for the next lists.
For 1 past moment, send `at` to [Get X trends](/api-reference/x/trends) instead.

## Query parameters

| Query parameter | Type      | Required | Description                                                                                                                                                                                                                                                                                                                                                                                                  |
| --------------- | --------- | -------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `woeid`         | `integer` | No       | Positive Where On Earth ID for the region. It wins over `country` and `location`. Invalid or nonpositive values fall back to those names, then to `1` (worldwide). [List trend locations](/api-reference/x/trend-locations) returns every place.                                                                                                                                                             |
| `country`       | `string`  | No       | Country to read trends history for, by name or 2-letter code. Examples are `Turkey` and `TR`. Case insensitive.                                                                                                                                                                                                                                                                                              |
| `location`      | `string`  | No       | Town or country to read trends history for, by name, such as `Istanbul`. Case insensitive. Add `country` when 2 towns share a name.                                                                                                                                                                                                                                                                          |
| `from`          | `string`  | No       | Start of the range. Takes an ISO 8601 time, a date such as `2026-10-13`, or Unix seconds. A time without a zone reads as UTC. It also takes a span back from now. A span is a number and `s`, `m`, `h`, or `d`. For example, `from=7d` reads the last 7 days. Defaults to 24 hours before `to`. History starts 2026-10-13 02:20 UTC. A range that begins earlier returns the stored part. Alias `sinceTime`. |
| `to`            | `string`  | No       | End of the range, which it leaves out. Takes the forms of `from`. For example, `from=2d` with `to=1d` reads the day before the last 24 hours. Defaults to now. Alias `untilTime`.                                                                                                                                                                                                                            |
| `every`         | `string`  | No       | Step between 2 returned lists, as a number and `m`, `h`, or `d`. Examples are `15m`, `1h`, and `1d`. Default `1h`. A step under `5m` returns every stored list.                                                                                                                                                                                                                                              |
| `count`         | `integer` | No       | Number of trends in each list. Default `30`, max `50`. Invalid or below-minimum values fall back to `30`.                                                                                                                                                                                                                                                                                                    |
| `limit`         | `integer` | No       | Maximum lists 1 request returns and charges. Default `24`, max `100`. Your credit balance can return fewer.                                                                                                                                                                                                                                                                                                  |
| `cursor`        | `string`  | No       | The `next_cursor` of the page before, for the next lists. It keeps the time of the first request. That way, a range of spans stays the same on every page.                                                                                                                                                                                                                                                   |

## Response

### 200 OK

| Field                    | Type       | Description                                                                                                                                                                       |
| ------------------------ | ---------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `snapshots`              | `object[]` | 1 stored list per step, oldest first. A step with no stored list is left out.                                                                                                     |
| `snapshots[].capturedAt` | `string`   | When Xquik read this list from X, as ISO 8601 in UTC. It comes from the stored list and is never estimated.                                                                       |
| `snapshots[].count`      | `number`   | Trends in this list.                                                                                                                                                              |
| `snapshots[].trends`     | `object[]` | The trends of the list, with the fields of [Get X trends](/api-reference/x/trends). `rank` is the trend's place in X's list at that time.                                         |
| `count`                  | `number`   | Lists returned and charged.                                                                                                                                                       |
| `fromTime`               | `string`   | Start of the range as Xquik read it, as ISO 8601 in UTC. A span such as `7d` shows here as the time it counted back to.                                                           |
| `toTime`                 | `string`   | End of the range as Xquik read it, which the range leaves out. Without `to`, it is the time of the first request.                                                                 |
| `woeid`                  | `number`   | WOEID used for the request.                                                                                                                                                       |
| `location`               | `object`   | The place `country` or `location` named, with the fields of a [trend location](/api-reference/x/trend-locations). Absent when `woeid` picked the place or the request named none. |
| `has_next_page`          | `boolean`  | Whether the range holds more lists.                                                                                                                                               |
| `next_cursor`            | `string`   | Send it as `cursor` for the next lists. Empty on the last page.                                                                                                                   |

### 400 Invalid input

The range ends before the place's first stored list. The message names that first time.
An unknown place and a `from` after `to` also return 400. So does a time or step Xquik cannot read.
The request costs nothing.

### 401 Unauthenticated

Anonymous requests get `WWW-Authenticate: Bearer` and a guest wallet checkout action. This is not a Payment challenge.

### 402 Payment required

Account keys get account options. Guest keys get guest top-up only.
No checkout starts automatically. Confirm any payment action.

### 502 X API unavailable

The read service returned an error. Retry after a short delay.

### 503 Service busy

Xquik is busy. Wait for `Retry-After`, then retry.

### 429 Rate limit exceeded

The Xquik tier limit blocked the request.
Use `Retry-After` when present. Otherwise, use the JSON `retryAfter` field.

### 424 Dependency failed

The opt-in normalized contract returns 424 when the read service fails.
Send `xquik-api-contract: 2026-04-29` to opt in. Default v1 returns 502.

## Twitter trends archive API questions

### How do I see what was trending on Twitter yesterday?

Call `GET /x/trends/history` with yesterday's date as `from` and today's date as `to`.
Add `every=1h` for 1 list per hour. Add `every=1d` for the first list of the day.

### How far back does the Twitter trends archive go?

It starts 2026-10-13 02:20 UTC. Xquik keeps each list for 25 months.
A range that ends before the start returns 400 and costs nothing.

### How often does Xquik store a list?

Every 5 minutes, for every place X offers trends for.
A step under `5m` returns every stored list.

### How much does trends history cost?

Each returned list costs 1 credit, so 24 lists cost 24 credits.
A step with no stored list costs nothing. A request returns 100 lists at most.

### What if no list matches a step?

The response leaves that step out. Xquik never fills a gap with a made-up list.
Each returned list states its own `capturedAt`.

### Does this replace X's official API?

No. This page documents Xquik, an independent third-party service.
It does not document X's official API.
