`GET https://xquik.com/api/v1/x/jobs/search`

Search the public job listings on X by keyword. Narrow them by location, work type, seniority, employment type, or company.

<Note>

Requested result counts are upper bounds for paid authenticated calls. When remaining credits cannot cover the full page, Xquik returns fewer results. If zero paid results are affordable, it returns `402 insufficient_credits`.

</Note>

<CodeGroup>

```bash cURL
curl "https://xquik.com/api/v1/x/jobs/search?q=engineer&locationType=remote&seniority=senior" \
  -H "x-api-key: xq_your_api_key_here" | jq
```

```javascript Node.js
const query = "engineer";
const params = new URLSearchParams({
  q: query,
  locationType: "remote",
  seniority: "senior,lead",
});
const response = await fetch(`https://xquik.com/api/v1/x/jobs/search?${params}`, {
  headers: { "x-api-key": "xq_your_api_key_here" },
});
const data = await response.json();
const nextCursor = data.has_next_page ? data.next_cursor : null;
const jobRows = data.jobs.map((job) => ({
  search_query: query,
  job_id: job.id,
  title: job.title ?? null,
  job_url: job.url,
  apply_url: job.applyUrl ?? null,
  location: job.location ?? null,
  salary: job.formattedSalary ?? null,
  employer: job.company?.name ?? job.account?.name ?? null,
  next_cursor: nextCursor,
}));
```

```python Python
import requests

query = "engineer"
response = requests.get(
    "https://xquik.com/api/v1/x/jobs/search",
    params={"q": query, "locationType": "remote", "seniority": "senior,lead"},
    headers={"x-api-key": "xq_your_api_key_here"},
)
data = response.json()
next_cursor = data["next_cursor"] if data["has_next_page"] else None
job_rows = [
    {
        "search_query": query,
        "job_id": job["id"],

        "job_url": job["url"],
        "apply_url": job.get("applyUrl"),

    }
```

<section>

## Narrow a job search

Start with a keyword in `q`, such as a job title or a skill. Add 1 filter at a time and check the results after each change.

- `location` takes a city, region, or country as text.
- `locationId` takes an exact place from [job locations](/api-reference/x/job-locations).
- `locationType` keeps onsite, remote, or hybrid jobs.
- `seniority` keeps levels from intern to executive.
- `employmentType` keeps full-time, part-time, or contract jobs.
- `company` keeps the jobs of 1 employer.

The 3 list filters take comma lists. They ignore case and accept spaces, hyphens, or underscores between words. `Full Time`, `full-time`, and `full_time` all work.

{"\n"}

An unknown value returns `400 invalid_job_filter`. Its message names the values the filter takes.

</section>

<section>

## Page through job listings

Each page returns `has_next_page` and `next_cursor`. Send `next_cursor` back as `cursor` with the same query and filters. Stop when `has_next_page` is `false`.

{"\n"}

A cursor X refuses or that expired returns `400 invalid_cursor`, which is free. Start again without `cursor`, then use `next_cursor`.

{"\n"}

A job that closed is left out of the page and costs nothing. A page can therefore hold fewer jobs than `pageSize`.

{"\n"}

Use the job `id` as the key in your store. Overlapping searches then add no duplicates.

</section>

<section>

## Get the full description

Search returns the listing summary. Send a job's `id` to [get 1 job listing](/api-reference/x/get-job). That listing adds the full description, work type, seniority, and team.

</section>

## Query parameters

| Query parameter  | Type      | Required | Description                                                                                                                            |
| ---------------- | --------- | -------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| `q`              | `string`  | Yes      | Keyword, such as a job title or skill. Also read as `query`.                                                                           |
| `location`       | `string`  | No       | City, region, or country as text, such as `Berlin`.                                                                                    |
| `locationId`     | `string`  | No       | Location ID from [job locations](/api-reference/x/job-locations). It replaces `location` when you send both.                           |
| `locationType`   | `string`  | No       | Where the work happens. Comma list of `onsite`, `remote`, and `hybrid`.                                                                |
| `seniority`      | `string`  | No       | Comma list of `intern`, `entry_level`, `junior`, `mid_level`, `senior`, `lead`, `manager`, and `executive`.                            |
| `employmentType` | `string`  | No       | Comma list of `full_time`, `full_time_contract`, `part_time`, and `contract_to_hire`.                                                  |
| `company`        | `string`  | No       | Company name to match.                                                                                                                 |
| `cursor`         | `string`  | No       | Pagination cursor from a previous response. Omit for the first page.                                                                   |
| `pageSize`       | `integer` | No       | Jobs per page. Accepts `1-100`. Defaults to `20`. Also read as `limit`, `count`, `max_results`, `maxItems`, `max_items` or `per_page`. |

### 400 Missing query, unknown filter, or invalid cursor

A request without `q` returns `missing_query`. A cursor X cannot read returns `invalid_cursor`.

{"\n"}

`{ "error": "invalid_cursor", "message": "Cursor invalid or expired. Start again without cursor, then use next_cursor." }`

{"\n"}

Start again without `cursor`. All 3 answers are free.

### 401 Unauthenticated

Anonymous requests get `WWW-Authenticate: Bearer` and a guest wallet checkout action. This is not a Payment challenge.

### 402 Payment required

Account keys get account options. Guest keys get guest top-up only.
No checkout starts automatically. Confirm any payment action.

### 502 X API unavailable

The read service returned an error. Retry after a short delay.

### 429 Rate limit exceeded

You exceeded your tier rate limit. Wait for the `Retry-After` header before retrying.

### 424 Dependency failed

The normalized v1 response contract can return 424 when the read service is unavailable.
