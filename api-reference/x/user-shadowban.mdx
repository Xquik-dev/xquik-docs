## Is an account shadowbanned on X?

Use `GET /x/users/{id}/shadowban` to run 4 checks on 1 account. Name the account by user ID, username, or profile URL.

- `account` reads whether the account is active, protected, or suspended.
- `search` looks for the account's recent posts in X search. It uses `from:username`, sorted by Latest.
- `suggestion` looks for the account among the accounts X suggests for its username.
- `replies` opens the threads of up to 3 recent replies to other accounts. It finds where each reply shows.

Each check answers `pass`, `fail`, or `unknown`. It adds a `reason` and the evidence it read. The reply check answers `pass`
or `unknown`, since X ranks replies for each viewer. A protected account gets the suggestion check only. A suspended
account gets the account check only.

## Response

### 200 OK

<ResponseField name="username" type="string | null">

Username of the account. `null` for a suspended account named by user ID.

</ResponseField>
<ResponseField name="userId" type="string | null">

ID of the account. `null` for a suspended account named by username.

</ResponseField>
<ResponseField name="account" type="string">

`active`, `protected`, or `suspended`.

</ResponseField>
<ResponseField name="checks" type="object">

The 4 checks. Each has `verdict`, `reason`, and `evidence`.

<ResponseField name="account" type="object">
  `pass` with `active` or `protected`, or `fail` with `suspended`. `evidence.profileUrl` opens the
  profile on X.
</ResponseField>
<ResponseField name="search" type="object">
  `pass` with `listed` or `fail` with `missing`. `evidence` holds `query`, `searchUrl`,
  `recentPostIds`, and `foundPostIds`.
</ResponseField>
<ResponseField name="suggestion" type="object">
  `pass` with `suggested` or `fail` with `not_suggested`. `evidence` holds `query` and
  `suggestedUsernames`.
</ResponseField>
<ResponseField name="replies" type="object">
  `pass` with `in_thread`, or `unknown` with `more_replies` or `not_found`. `evidence.replies` lists
  each reply with its `placement`, `replyUrl`, and `parentUrl`.
</ResponseField>

</ResponseField>

### 400 Invalid input

```json
{ "error": "invalid_user_id" }
```

Send a user ID, a username, or a profile URL.

### 404 User not found

```json
{ "error": "user_not_found", "message": "X user not found. Check the username." }
```

A user X does not know is free of charge.

### 401 Unauthenticated

Anonymous requests get `WWW-Authenticate: Bearer` and a guest wallet checkout action. This is not a Payment challenge.

```json
{ "error": "unauthenticated" }
```

### 402 Payment required

Account keys get account options. Guest keys get guest top-up only.
No checkout starts automatically. Confirm any payment action.

### 502 X API unavailable

```json
{ "error": "x_api_unavailable" }
```

The read service returned an error. Retry after a short delay.
