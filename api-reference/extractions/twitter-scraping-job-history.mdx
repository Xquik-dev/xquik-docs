## Query parameters

| Query parameter | Type     | Required | Description                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| --------------- | -------- | -------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `limit`         | `number` | No       | Number of extractions to return per page. Defaults to `50`. | `toolType`      | `string` | No       | Filter by tool type. | `status`        | `string` | No       | Filter by job status. Use `completed`, `failed`, or `running`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| `cursor`        | `string` | No       | Cursor for pagination. Use the `nextCursor` value from the previous response to fetch the next page.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |

| Scraping job inventory column | Response source              | Reconciliation rule                                    |
| ----------------------------- | ---------------------------- | ------------------------------------------------------ |
| Job ID                        | `extractions[].id`           | Open the matching extraction result pages.             |
| Scraper tool                  | `extractions[].toolType`     | Separate tweet, follower, reply, and profile jobs.     |
| Job state                     | `extractions[].status`       | Handle completed, failed, and running jobs separately. |
| Extracted rows                | `extractions[].totalResults` | Compare this count with saved result pages.            |
| Started at                    | `extractions[].createdAt`    | Keep the collection start time.                        |
| Completed at                  | `extractions[].completedAt`  | Measure completed-job duration.                        |
| More jobs                     | `hasMore`                    | Continue only while this value is `true`.              |
| Next page                     | `nextCursor`                 | Pass this value as the next `cursor` parameter.        |

## Response

### 200 OK

| Field                        | Type       | Description                                                                    |
| ---------------------------- | ---------- | ------------------------------------------------------------------------------ |
| `extractions`                | `object[]` | Array of extraction job summaries.                                             |
| `extractions[].id`           | `string`   | Unique extraction job ID.                                                      |
| `extractions[].toolType`     | `string`   | Tool type used for this extraction.                                            |
| `extractions[].status`       | `string`   | The job status is `completed`, `failed`, or `running`.                         |
| `extractions[].totalResults` | `number`   | Total number of extracted results.                                             |
| `extractions[].createdAt`    | `string`   | ISO 8601 timestamp of when the job was created.                                |
| `extractions[].completedAt`  | `string`   | ISO 8601 timestamp of when the job finished. Only present for completed jobs.  |

## Pagination

The API orders results by creation date, newest first. Follow these steps to read every extraction.

1. Make the initial request without the `cursor` parameter.
2. Check `hasMore`. Pass `nextCursor` as the next `cursor` value.
3. Repeat until `hasMore` is `false`.

```javascript
import { appendFile } from "node:fs/promises";

let cursor = undefined;
let pageIndex = 0;

do {
  const params = new URLSearchParams({
    limit: "100",
    status: "completed",
  });
  if (cursor) params.set("cursor", cursor);
  const pageCursor = cursor ?? null;

  const response = await fetch(`https://xquik.com/api/v1/extractions?${params}`, {
    headers: { "x-api-key": "xq_YOUR_KEY_HERE" },
  });
  const data = await response.json();

  const rows = data.extractions.map((job) => ({
    extraction_id: job.id,
    tool_type: job.toolType,
    status: job.status,
    total_results: job.totalResults,
    created_at: job.createdAt,
    completed_at: job.completedAt ?? null,
    detail_path: `/api/v1/extractions/${job.id}`,
    export_path:
      job.status === "completed" ? `/api/v1/extractions/${job.id}/export?format=csv` : null,
    page_index: pageIndex,
    page_cursor: pageCursor,
    next_cursor: data.nextCursor ?? null,
    has_more: data.hasMore,
    handoff_format: "jsonl",
  }));

  if (rows.length > 0) {
    await appendFile(
      "xquik-extraction-jobs.jsonl",
      `${rows.map((row) => JSON.stringify(row)).join("\n")}\n`,
    );
  }

  cursor = data.hasMore ? data.nextCursor : undefined;
  pageIndex += 1;
} while (cursor);
```

## Job inventory handoff

Use `GET /extractions` as the job inventory step before fetching details or
exporting files. Treat `nextCursor` as opaque and pass it back as `cursor`. Do
not write raw job lists to shared logs.

<CardGroup cols={2}>

  <Card title="Page checkpoint" icon="bookmark">

    Store `page_index`, `page_cursor`, `next_cursor`, `has_more`, `limit`,
    `tool_type_filter`, and `status_filter` after each successful page.

  </Card>
  <Card title="Completed jobs" icon="circle-check">

    Store these completed job fields for the next fetch or file export. They are
    `id`, `toolType`, `totalResults`, `completedAt`, `detail_path`, and
    `export_path`.

  </Card>
  <Card title="Running or failed jobs" icon="circle-alert">

    Keep `status`, `createdAt`, and `id`. That lets dashboards retry failed jobs
    or poll running jobs without rereading older pages.

  </Card>
  <Card title="Next API step" icon="route">

    Use [Get Extraction](/api-reference/extractions/twitter-extraction-results) for paginated JSON
    rows, or [Export Extraction](/api-reference/extractions/export) for files.

  </Card>
</CardGroup>

Store page checkpoints separately from job rows.
