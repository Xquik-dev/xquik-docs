```bash cURL
curl --fail -X GET "https://xquik.com/api/v1/extractions/a1b2c3d4-e5f6-7890-abcd-ef1234567890/export?format=csv" \
  -H "x-api-key: xq_YOUR_KEY_HERE" \
  -o extraction-reply_extractor.csv
```

```javascript Node.js
import { writeFile } from "node:fs/promises";

const extractionId = "a1b2c3d4-e5f6-7890-abcd-ef1234567890";
const response = await fetch(
  `https://xquik.com/api/v1/extractions/${extractionId}/export?format=csv`,
  {
    method: "GET",
    headers: {
      "x-api-key": "xq_YOUR_KEY_HERE",
    },
  },
);

if (!response.ok) {
  throw new Error(`Export failed with ${response.status}`);
}

const bytes = Buffer.from(await response.arrayBuffer());
await writeFile("extraction-reply_extractor.csv", bytes);
```

```python Python
import requests

extraction_id = "a1b2c3d4-e5f6-7890-abcd-ef1234567890"
response = requests.get(
    f"https://xquik.com/api/v1/extractions/{extraction_id}/export",
    headers={"x-api-key": "xq_YOUR_KEY_HERE"},
    params={"format": "csv"},
)
response.raise_for_status()

with open("extraction-reply_extractor.csv", "wb") as f:
    f.write(response.content)
```

```go Go
package main

import (
    "fmt"
    "io"
    "net/http"
    "os"
)

func main() {
    req, err := http.NewRequest("GET", "https://xquik.com/api/v1/extractions/a1b2c3d4-e5f6-7890-abcd-ef1234567890/export?format=csv", nil)
    if err != nil {
        panic(err)
    }
    req.Header.Set("x-api-key", "xq_YOUR_KEY_HERE")

    resp, err := http.DefaultClient.Do(req)
    if err != nil {
        panic(err)
    }
    defer resp.Body.Close()

    if resp.StatusCode < 200 || resp.StatusCode >= 300 {
        panic(fmt.Sprintf("export failed with %d", resp.StatusCode))
    }

    file, err := os.Create("extraction-reply_extractor.csv")
    if err != nil {
        panic(err)
    }
    defer file.Close()

    if _, err := io.Copy(file, resp.Body); err != nil {
        panic(err)
    }
}
```

## File handoff

Treat the response body as file bytes. Save it first. Then pass the local path
to the CRM import, warehouse load, queue, or agent. Do not print downloaded export
bytes to shared logs.

```json
{
  "extraction_id": "a1b2c3d4-e5f6-7890-abcd-ef1234567890",
  "export_format": "csv",
  "export_file_path": "extraction-reply_extractor.csv",
  "content_type": "text/csv; charset=utf-8",
  "handoff_format": "file"
}
```

The response `Content-Disposition` header contains the server filename. Store it
when you need an audit trail. The trail connects the downloaded file to the
extraction job.

### Format handoff map

<CardGroup cols={2}>

  <Card title="CRM CSV" icon="table">

    Use `format=csv` for CRM imports, spreadsheet checks, and follower or reply
    upserts. Name reply jobs `xquik-replies.csv` and follower jobs
    `xquik-followers.csv`.

  </Card>
  <Card title="App JSON" icon="braces">

    Use `format=json` for app ingestion, queue replay, or structured storage.
    Each row keeps the nested `enrichmentData` of its result, with media and
    entities. Store the extraction ID and server filename with the local path.

  </Card>
  <Card title="Analyst XLSX" icon="file-spreadsheet">

    Use `format=xlsx` for analyst review and account-management workbooks when
    people need filters or formulas.

  </Card>
  <Card title="Report formats" icon="file-text">

    Use `format=md`, `md-document`, `pdf`, or `txt` for human-readable reports.
    Xquik caps PDF at 10,000 rows.

  </Card>
</CardGroup>

For exports above 100,000 rows, use
[Extraction Workflow](/guides/extraction-workflow#durable-json-lines-handoff).
With it, write JSON Lines from paginated `GET /extractions/{id}` results.

## Query parameters

| Query parameter | Type     | Required | Description                                                                          |
| --------------- | -------- | -------- | ------------------------------------------------------------------------------------ |
| `format`        | `string` | Yes      | Export file format. Use `csv`, `json`, `md`, `md-document`, `pdf`, `txt`, or `xlsx`. |

### Export filters

| Query parameter     | Type      | Required | Description                                                                                                                                                                              |
| ------------------- | --------- | -------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `minFollowers`      | `integer` | No       | Minimum follower count.                                                                                                                                                                  |
| `maxFollowers`      | `integer` | No       | Maximum follower count.                                                                                                                                                                  |
| `minFollowing`      | `integer` | No       | Minimum following count.                                                                                                                                                                 |
| `maxFollowing`      | `integer` | No       | Maximum following count.                                                                                                                                                                 |
| `minPosts`          | `integer` | No       | Minimum post count.                                                                                                                                                                      |
| `maxPosts`          | `integer` | No       | Maximum post count.                                                                                                                                                                      |
| `minLikes`          | `integer` | No       | Minimum like count.                                                                                                                                                                      |
| `minReplies`        | `integer` | No       | Minimum reply count.                                                                                                                                                                     |
| `minRetweets`       | `integer` | No       | Minimum repost count.                                                                                                                                                                    |
| `minViews`          | `integer` | No       | Minimum view count.                                                                                                                                                                      |
| `hasDescription`    | `boolean` | No       | Require a non-empty description.                                                                                                                                                         |
| `hasLocation`       | `boolean` | No       | Require a non-empty location.                                                                                                                                                            |
| `compare`           | `string`  | No       | ID of an earlier run that read the same account's whole list. The export then holds only the rows that differ.                                                                           |
| `change`            | `string`  | No       | With `compare`, `added` keeps this run's new rows. `removed` keeps the earlier run's rows that this run lacks. The default is `added`.                                                   |
| `hasWebsite`        | `boolean` | No       | Require a website on the profile.                                                                                                                                                        |
| `joinedSince`       | `string`  | No       | Keep accounts that joined X on this UTC day or later, as `YYYY-MM-DD`.                                                                                                                   |
| `joinedUntil`       | `string`  | No       | Keep accounts that joined X before this UTC day, as `YYYY-MM-DD`.                                                                                                                        |
| `location`          | `string`  | No       | Keep accounts whose location contains this text.                                                                                                                                         |
| `hideInactive`      | `boolean` | No       | Drop accounts at least 180 days old that average under 1 post a month.                                                                                                                   |
| `hideFake`          | `boolean` | No       | Drop accounts with at least 3 of 4 signs. The signs are no posts, a default picture and an empty bio. The fourth is following at least 100 accounts and 10 times their followers.        |
| `hasEmail`          | `boolean` | No       | Require an email in the row's `Email` column.                                                                                                                                            |
| `businessEmailOnly` | `boolean` | No       | Require an email outside free webmail, such as Gmail, in the `Email` column.                                                                                                             |
| `emailDomains`      | `string`  | No       | Require the row's email at one of these comma-separated domains. An export filters on a profile's first email. A job filters on every email.                                             |
| `hasMedia`          | `boolean` | No       | Require media.                                                                                                                                                                           |
| `verified`          | `boolean` | No       | Match verified status.                                                                                                                                                                   |
| `lang`              | `string`  | No       | Match a language code.                                                                                                                                                                   |
| `search`            | `string`  | No       | Search exported result text.                                                                                                                                                             |
| `sinceDate`         | `string`  | No       | Include results on or after this date, from 00:00 UTC. An ISO 8601 time starts at that instant. Results without a post date are left out. An empty value sets no filter.                 |
| `untilDate`         | `string`  | No       | Include results on or before this date, inclusive, through 23:59:59 UTC. An ISO 8601 time ends at that instant. Results without a post date are left out. An empty value sets no filter. |

## Export columns

The extraction tool type decides the columns. Default exports include 33
columns. `article_extractor` exports 11 article columns. JSON rows also keep
each result's nested `enrichmentData`, as
[Get Extraction](/api-reference/extractions/twitter-extraction-results) returns it.

### Default result columns

All extraction tools except `article_extractor` use the default result column set. Some enrichment columns may be empty when the result does not include that data.

<CardGroup cols={2}>

  <Card title="User identity" icon="user">

    `User ID`, `Username`, `Display Name`, `Verified`, and `Profile Image`.

  </Card>
  <Card title="Audience metrics" icon="chart-no-axes-column">

    `Followers`, `Following`, `Posts`, `Media Count`, and `Favorites`.

  </Card>
  <Card title="Profile context" icon="file-text">

    `Description`, `Location`, `Email`, `Phones`, `Links`, and `Cover Picture`.
    `Email` holds the first email the profile publishes. `Phones` & `Links` hold every number &
    link it publishes, joined by a comma & a space.

  </Card>
  <Card title="Tweet content" icon="message-square">

    `Tweet ID`, `Tweet URL`, `Tweet Text`, and `Tweet Created At`.
    `Tweet URL` falls back to the status URL when the username is unavailable.

  </Card>
  <Card title="Tweet engagement" icon="activity">

    `Likes`, `Reposts`, `Replies`, `Quotes`, `Views`, and `Bookmarks`.

  </Card>
  <Card title="Tweet metadata" icon="braces">

    `Language`, `Source`, and `Conversation ID`.

  </Card>
  <Card title="Article metadata" icon="file-text">

    `Article Title`, `Article Preview`, `Article Body`, and `Article Contents JSON`.

  </Card>
</CardGroup>

### Article extractor columns

`article_extractor` uses a shorter column set for articles.

<CardGroup cols={2}>

  <Card title="Article identity" icon="file-text">

    `Article Title`, `Cover Image`, `Article Body`, and `Article Contents JSON`.

  </Card>
  <Card title="Author identity" icon="user">

    `Author`, `Username`, and `Verified`.

  </Card>
  <Card title="Author reach" icon="chart-no-axes-column">

    `Followers`.

  </Card>
  <Card title="Article engagement" icon="activity">

    `Views`, `Likes`, and `Quotes`.

  </Card>
</CardGroup>

## Response

<Tabs>

  <Tab title="200 OK">

    Returns a file download. The response includes a `Content-Disposition` header with the filename.

    <CardGroup cols={2}>

      <Card title="CSV" icon="table">

        `format=csv` returns `text/csv; charset=utf-8` with filenames like
        `extraction-reply_extractor-*.csv`.

      </Card>
      <Card title="JSON" icon="braces">

        `format=json` returns `application/json; charset=utf-8` with filenames
        like `extraction-reply_extractor-*.json`. Each row adds the result's
        nested `enrichmentData` to its columns.

      </Card>
      <Card title="Markdown" icon="file-text">

        `format=md` returns `text/markdown; charset=utf-8` with filenames like
        `extraction-reply_extractor-*.md`.

      </Card>
      <Card title="Markdown document" icon="file-text">

        `format=md-document` returns `text/markdown; charset=utf-8` with
        filenames like `extraction-reply_extractor-*.md`.

      </Card>
      <Card title="PDF" icon="file-down">

        `format=pdf` returns `application/pdf` with filenames like
        `extraction-reply_extractor-*.pdf`.

      </Card>
      <Card title="TXT" icon="file">

        `format=txt` returns `text/plain; charset=utf-8` with filenames like
        `extraction-reply_extractor-*.txt`.

      </Card>
      <Card title="XLSX" icon="file-spreadsheet">

        `format=xlsx` returns
        `application/vnd.openxmlformats-officedocument.spreadsheetml.sheet`
        with filenames like `extraction-reply_extractor-*.xlsx`.

      </Card>
    </CardGroup>

    Exports stop at 100,000 rows (10,000 for PDF). For extractions with more results, the export includes the first 100,000 rows. It orders them by result ID.

  </Tab>
  <Tab title="400 Invalid format">

    ```json
    {
      "error": "invalid_format",
      "validFormats": ["csv", "json", "md", "md-document", "pdf", "txt", "xlsx"]
    }
    ```
    The `format` query parameter is missing or not one of the supported values.

  </Tab>
  <Tab title="401 Unauthenticated">

    ```json
    { "error": "unauthenticated" }
    ```
    Missing or invalid API key.

  </Tab>
  <Tab title="404 Not found">

    ```json
    { "error": "not_found" }
    ```
    No extraction job exists with this ID, or it belongs to a different account.

  </Tab>
  <Tab title="429 Rate limited">

    ```json
    { "error": "rate_limit_exceeded", "message": "Too many requests. Try again later.", "retryAfter": 1 }
    ```
    Wait for the `Retry-After` value before requesting another export.

  </Tab>
</Tabs>
