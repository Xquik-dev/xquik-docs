Each request bookmarks 1 tweet by ID.
Each request uses 1 connected X account.
Only that account sees its bookmarks.
Create a unique `Idempotency-Key` for the intended bookmark.
Store the returned write action and poll `statusUrl` when needed.

```bash cURL
curl -X POST https://xquik.com/api/v1/x/tweets/1895432178065391234/bookmark \
  -H "x-api-key: xq_YOUR_KEY_HERE" \
  -H "Idempotency-Key: bookmark-1895432178065391234" \
  -H "Content-Type: application/json" \
  -d '{"account":"elonmusk"}' | jq '{
    status,

    safe_to_retry: .safeToRetry,
    write_action_id: .id,
    requested_tweet_id: "1895432178065391234",

    charged_credits: .billing.chargedCredits,
```

```javascript Node.js
const tweetId = "1895432178065391234";
const response = await fetch(`https://xquik.com/api/v1/x/tweets/${tweetId}/bookmark`, {
  method: "POST",
  headers: {
    "x-api-key": "xq_YOUR_KEY_HERE",
    "Idempotency-Key": "bookmark-1895432178065391234",
    "Content-Type": "application/json",
  },
  body: JSON.stringify({ account: "elonmusk" }),
});
const result = await response.json();
if (!response.ok) {
  throw new Error(JSON.stringify(result));
}
const bookmarkRecord = {
  status: result.status,
  terminal: result.terminal,
  safe_to_retry: result.safeToRetry,
  write_action_id: result.id,
  requested_tweet_id: tweetId,
  confirmed_tweet_id: result.result?.id ?? result.targetId ?? null,
  charged_credits: result.billing.chargedCredits,
  poll_path: result.terminal ? null : result.statusUrl,
};
process.stdout.write(`${JSON.stringify(bookmarkRecord)}\n`);
```

```python Python
import json
import requests

tweet_id = "1895432178065391234"
response = requests.post(
    f"https://xquik.com/api/v1/x/tweets/{tweet_id}/bookmark",
    headers={
        "x-api-key": "xq_YOUR_KEY_HERE",
        "Idempotency-Key": "bookmark-1895432178065391234",
    },
    json={"account": "elonmusk"},
)
result = response.json()
response.raise_for_status()
bookmark_record = {
    "status": result["status"],
    "terminal": result["terminal"],
    "safe_to_retry": result["safeToRetry"],
    "write_action_id": result["id"],
    "requested_tweet_id": tweet_id,
    "confirmed_tweet_id": (result.get("result") or {}).get("id") or result.get("targetId"),
    "charged_credits": result["billing"]["chargedCredits"],
    "poll_path": None if result["terminal"] else result["statusUrl"],
}
print(json.dumps(bookmark_record))
```

<section>

## Bookmark one tweet by ID

Put the exact Tweet ID in the request path.
Put the connected account username or ID in the body.
That account saves the bookmark.

{"\n"}

Copy Tweet IDs as strings.
JavaScript numbers cannot represent every X identifier exactly.
This endpoint accepts 1 Tweet ID per request.

</section>

<section>

## Keep bookmarks private to the acting account

X shows a bookmark only to the account that saved it.
The post's author sees a bookmark count, never who saved it.
Bookmarking never notifies the author or adds a like.

{"\n"}

Read the saved posts with [Bookmarks](/api-reference/x/bookmarks).

</section>

<section>

## Save a bookmark receipt

Save the action first. Then update your reading list.

| Bookmark action column | Source                 | Rule                                                                      |
| ---------------------- | ---------------------- | ------------------------------------------------------------------------- |
| `acting_account`       | Request `account`      | Keep the connected X account with the bookmark.                           |
| `tweet_id`             | Path `id`              | Keep the exact Tweet ID the user picked.                                  |
| `idempotency_key`      | Request header         | Generate <span className="nw">1 key</span> for this account and Tweet ID. |
| `write_action_id`      | Response `id`          | Store the action before polling.                                          |
| `terminal`             | Response `terminal`    | Mark the bookmark saved only when `true`.                                 |
| `safe_to_retry`        | Response `safeToRetry` | Retry only when this value is `true`.                                     |

</section>

<section>

## Choose bookmark, like, or read bookmarks

| Intent                   | API route                        | Result                                    |
| ------------------------ | -------------------------------- | ----------------------------------------- |
| Save one tweet privately | `POST /x/tweets/{id}/bookmark`   | Adds the post to the account's bookmarks. |
| Remove one saved tweet   | `DELETE /x/tweets/{id}/bookmark` | Removes the post from the bookmarks.      |
| Read saved tweets        | `GET /x/bookmarks`               | Returns the account's bookmarked posts.   |
| Like one tweet in public | `POST /x/tweets/{id}/like`       | Adds a public like instead.               |

Use [Remove bookmark](/api-reference/x-write/unbookmark) to reverse a bookmark.

</section>

<section>

## Twitter bookmark API questions

### Can an API bookmark a tweet by ID?

Yes. Send the Tweet ID in the path and the connected account in the body.

### Can other people see the bookmark?

No. X shows bookmarks only to the account that saved them.
The author sees the total bookmark count on the post.

</section>

<section>

## Handle errors

Never infer failure from a client timeout.
Poll a returned action before sending another request.

- For `400`, correct the Tweet ID or account value.
- For `401`, replace invalid Xquik authentication.
- For `402`, add credits before another request.
- For `403`, reconnect the selected X account.
- For `409`, keep the original action and payload.
- For `422`, review the X rejection before retrying.
- For `429`, wait for `Retry-After`.
- For <span className="nw">`500` or</span> `503`, follow `safeToRetry` and `terminal`.

</section>

## Headers

| Header            | Type     | Required | Description                                                                                                        |
| ----------------- | -------- | -------- | ------------------------------------------------------------------------------------------------------------------ |
| `x-api-key`       | `string` | No       | Send your Xquik API key in this header. Alternatively, send an OAuth <span className="nw">2.1 bearer</span> token. |
| `Authorization`   | `string` | No       | Send `Bearer <token>` instead of `x-api-key` when using OAuth 2.1.                                                 |
| `Idempotency-Key` | `string` | Yes      | Unique key for this intended write. Reuse it only for an exact network replay.                                     |
| `Content-Type`    | `string` | Yes      | Must be `application/json`.                                                                                        |

</section>

<section>

## Path parameters

| Path parameter | Type     | Required | Description                                                                                                                                    |
| -------------- | -------- | -------- | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| `id`           | `string` | Yes      | Post ID or <span className="nw">URL-encoded</span> post URL, such as `x.com/nasa/status/20`. See [path IDs](/api-reference/overview#path-ids). |

</section>

## Body

| Body parameter | Type     | Required | Description                                                                                                                    |
| -------------- | -------- | -------- | ------------------------------------------------------------------------------------------------------------------------------ |
| `account`      | `string` | Yes      | X (Twitter) username or account ID of the connected account that bookmarks the tweet. Xquik strips the `@` prefix if included. |
