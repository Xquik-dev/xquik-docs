## Delete a direct message with the Twitter DM API

This route deletes 1 DM from the connected account's side of the conversation.
The other person still sees it.
Xquik charges 10 credits only when X deletes the DM.

{"\n"}

Put the other person in the path and the DM ID in `messageId`.
[DM history](/api-reference/x/dm-history) and [Send DM](/api-reference/x-write/send-dm) return DM IDs.
Send your connected account in the `account` query parameter.

<CodeGroup>

```bash cURL
curl -X DELETE "https://xquik.com/api/v1/x/dm/44196397/messages/1893726451029384192?account=myxaccount" \
  -H "x-api-key: xq_YOUR_KEY_HERE" \
  -H "Idempotency-Key: dm-delete-1893726451029384192" | jq
```

```javascript Node.js
const userId = "44196397";
const messageId = "1893726451029384192";
const url = new URL(`https://xquik.com/api/v1/x/dm/${userId}/messages/${messageId}`);
url.searchParams.set("account", "myxaccount");

const response = await fetch(url, {
  method: "DELETE",
  headers: {
    "x-api-key": "xq_YOUR_KEY_HERE",
    "Idempotency-Key": `dm-delete-${messageId}`,
  },
});
const action = await response.json();
if (!response.ok) {
  throw new Error(action.message);
}

process.stdout.write(`${JSON.stringify(action)}\n`);
```

## Confirm the delete

Xquik confirms the DM is deleted before it reports success.
A `200` response means the DM is gone.
Its `result` has `type: "state_change"`, the DM `id` and `state: "deleted"`.

{"\n"}

A `202` response means Xquik has not confirmed the delete yet.
Poll `statusUrl` until `terminal` is `true`.
You pay nothing while the delete is pending.

{"\n"}

Deleting the same DM again also succeeds.

</section>

<section>

## Handle delete DM errors

- `400 invalid_`<span className="cn"><wbr />`message_id`</span> means `messageId` is not a DM ID. Copy it from DM history.
- `400 account_required` means the `account` query parameter is missing.
- `404 account_not_`<span className="cn"><wbr />`found`</span> means the account is not connected to Xquik.
- `422 x_dm_not_deleted` means X still shows the DM. You pay nothing, and `safeToRetry` is `true`.

Every other status follows the write rules below.
See [error handling](/guides/error-handling) for each code.

</section>

<section>

## Headers

| Header            | Type     | Required | Description                                                                                                                                            |
| ----------------- | -------- | -------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `x-api-key`       | `string` | Yes      | Your API key. OAuth bearer authentication is also supported. Generate a key from the [dashboard](https://dashboard.xquik.com/en/account?tab=api-keys). |
| `Idempotency-Key` | `string` | Yes      | Unique key for this intended delete. Reuse it only for an exact network replay.                                                                        |

</section>

<section>

## Path parameters

| Path parameter | Type     | Required | Description                                                                                                                                                                                                                      |
| -------------- | -------- | -------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `userId`       | `string` | Yes      | The other person in the conversation. Send a user ID or a username with or without `@`. A <span className="nw">URL-encoded</span> profile URL such as `x.com/nasa` also works. See [path IDs](/api-reference/overview#path-ids). |
| `messageId`    | `string` | Yes      | DM ID from DM history. Anything else returns `400 invalid_message_id`.                                                                                                                                                           |

</section>

<section>

## Query parameters

| Query parameter | Type     | Required | Description                                                                                                                         |
| --------------- | -------- | -------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| `account`       | `string` | Yes      | X (Twitter) username or account ID of the connected account that sees the DM. Without it, the route returns `400 account_required`. |

</section>
