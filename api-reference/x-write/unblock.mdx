## Unblock one user by ID

Put the exact user ID in the request path.
Put the connected account username or ID in the body.
That account unblocks the user.

Follow the user again with [Follow user](/api-reference/x-write/follow) if needed.

## Save a receipt

Save the action first. Then update your local record.

| Column            | Source                 | Rule                                          |
| ----------------- | ---------------------- | --------------------------------------------- |
| `acting_account`  | Request `account`      | Keep the connected X account with the action. |
| `user_id`         | Path `id`              | Keep the exact user ID.                       |
| `idempotency_key` | Request header         | Generate 1 key for this account and user ID.  |
| `write_action_id` | Response `id`          | Store the action before polling.              |
| `terminal`        | Response `terminal`    | Change the local record only when `true`.     |
| `safe_to_retry`   | Response `safeToRetry` | Retry only when this value is `true`.         |

## Handle errors

Never infer failure from a client timeout.
Poll a returned action before sending another request.

- For `400`, correct the user ID or account value.
- For `401`, replace invalid Xquik authentication.
- For `402`, add credits before another request.
- For `403`, reconnect the selected X account.
- For `409`, keep the original action and payload.
- For `422`, review the X rejection before retrying.
- For `429`, wait for `Retry-After`.
- For `500` or `503`, follow `safeToRetry` and `terminal`.

## Headers

<ParamField header="x-api-key" type="string">

Send your Xquik API key in this header. Alternatively, send an OAuth 2.1 bearer token.

</ParamField>

<ParamField header="Authorization" type="string">

Send `Bearer <token>` instead of `x-api-key` when using OAuth 2.1.

</ParamField>

<ParamField header="Idempotency-Key" type="string" required>

Unique key for this intended write. Reuse it only for an exact network replay.

</ParamField>

<ParamField header="Content-Type" type="string" required>

Must be `application/json`.

</ParamField>

## Path parameters

<ParamField path="id" type="string" required>

User to unblock. Send a user ID or a username with or without `@`. A URL-encoded profile URL such as `x.com/nasa` also works.
An unknown username returns `422 x_target_not_found`. See [path IDs](/api-reference/overview#path-ids).

</ParamField>

## Body

<ParamField body="account" type="string" required>

X username or account ID identifying which connected X account acts. Xquik strips the `@` prefix if included.

</ParamField>
