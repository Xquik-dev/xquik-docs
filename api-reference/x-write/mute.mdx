<section>

## Mute one user by ID

Put the exact user ID in the request path.
Put the connected account username or ID in the body.
That account mutes the user.

{"\n"}

The user's posts leave that account's home timeline.
The user can still follow, reply and mention the account.

{"\n"}

Use [Unmute user](/api-reference/x-write/unmute) to reverse a mute.

</section>

<section>

## Save a receipt

Save the action first. Then update your local record.

| Column            | Source                 | Rule                                          |
| ----------------- | ---------------------- | --------------------------------------------- |
| `acting_account`  | Request `account`      | Keep the connected X account with the action. |
| `user_id`         | Path `id`              | Keep the exact user ID.                       |
| `idempotency_key` | Request header         | Generate 1 key for this account and user ID.  |
| `write_action_id` | Response `id`          | Store the action before polling.              |
| `terminal`        | Response `terminal`    | Change the local record only when `true`.     |
| `safe_to_retry`   | Response `safeToRetry` | Retry only when this value is `true`.         |

</section>

<section>

## Handle errors

Never infer failure from a client timeout.
Poll a returned action before sending another request.

- For `400`, correct the user ID or account value.
- For `401`, replace invalid Xquik authentication.
- For `402`, add credits before another request.
- For `403`, reconnect the selected X account.
- For `409`, keep the original action and payload.
- For `422`, review the X rejection before retrying.
- For `429`, wait for `Retry-After`.
- For `500` or `503`, follow `safeToRetry` and `terminal`.

</section>

<section>

## Headers

| Header            | Type     | Required | Description                                                                            |
| ----------------- | -------- | -------- | -------------------------------------------------------------------------------------- |
| `x-api-key`       | `string` | No       | Send your Xquik API key in this header. Alternatively, send an OAuth 2.1 bearer token. |
| `Authorization`   | `string` | No       | Send `Bearer <token>` instead of `x-api-key` when using OAuth 2.1.                     |
| `Idempotency-Key` | `string` | Yes      | Unique key for this intended write. Reuse it only for an exact network replay.         |
| `Content-Type`    | `string` | Yes      | Must be `application/json`.                                                            |

</section>

<section>

## Path parameters

| Path parameter | Type     | Required | Description                                                                                                                                                                                                                        |
| -------------- | -------- | -------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `id`           | `string` | Yes      | User to mute. Send a user ID or a username with or without `@`. A URL-encoded profile URL such as `x.com/nasa` also works. An unknown username returns `422 x_target_not_found`. See [path IDs](/api-reference/overview#path-ids). |

</section>

<section>

## Body

| Body parameter | Type     | Required | Description                                                                                                   |
| -------------- | -------- | -------- | ------------------------------------------------------------------------------------------------------------- |
| `account`      | `string` | Yes      | X username or account ID identifying which connected X account acts. Xquik strips the `@` prefix if included. |

</section>
