```go Go
package main

import (
	"bytes"
	"encoding/json"
	"log"
	"net/http"
)

func main() {
	payload := map[string]interface{}{
		"url":        "https://your-server.com/webhook",
		"eventTypes": []string{"tweet.new", "tweet.reply"},
	}
	body, err := json.Marshal(payload)
	if err != nil {
		log.Fatal(err)
	}

	req, err := http.NewRequest("POST", "https://xquik.com/api/v1/webhooks", bytes.NewReader(body))
	if err != nil {
		log.Fatal(err)
	}
	req.Header.Set("x-api-key", "xq_YOUR_KEY_HERE")
	req.Header.Set("Content-Type", "application/json")

	resp, err := http.DefaultClient.Do(req)
	if err != nil {
		log.Fatal(err)
	}
	defer resp.Body.Close()

  var webhook map[string]any
  if err := json.NewDecoder(resp.Body).Decode(&webhook); err != nil {
		log.Fatal(err)
	}
  secret, _ := webhook["secret"].(string)
  // Store secret in your secret manager; do not print it in logs.
  _ = secret
}
```

## Body

| Body parameter | Type       | Required | Description                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| -------------- | ---------- | -------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `url`          | `string`   | Yes      | HTTPS endpoint URL where Xquik delivers events. Xquik rejects HTTP URLs. It also rejects URLs resolving to private or internal IP addresses. These are localhost, 10.x.x.x, 172.16-31.x.x, 192.168.x.x, and 169.254.x.x.<br />A Discord channel webhook URL, such as `https://discord.com/api/webhooks/...`, gets alerts as Discord messages.<br />A Slack incoming webhook URL, such as `https://hooks.slack.com/services/...`, gets alerts as Slack messages.<br />- The events of 1 post come as 1 alert. An example title is "New post with media".<br />- Alerts that wait together come as 1 message.<br />- A busy channel gets 5 quick messages, then 1 every 30 seconds.<br />- Each event keeps its own delivery. With it, retries and resume work as for any webhook. |
| `eventTypes`   | `string[]` | Yes      | Array of event types to subscribe to. At least 1 required. Use any valid account monitor event type listed below. Keyword monitors emit only `tweet.*` event types. Account monitors can emit both `tweet.*` and `profile.*` event types. [Post monitors](/api-reference/monitors/create-post) emit only `post.*` event types.                                                                                                                                                                                                                                                                                                                                                                                                                                                   |

## Valid event types

Valid types are `tweet.new`, `tweet.quote`, `tweet.reply`, `tweet.retweet`,
`tweet.media`, `tweet.link`, `tweet.poll`, `tweet.mention`, `tweet.hashtag`,
`tweet.longform`. Valid types are also `profile.avatar.changed`,
`profile.banner.changed`, `profile.name.changed`, `profile.username.changed`,
`profile.bio.changed`, `profile.location.changed`, `profile.url.changed`,
`profile.verified.changed`, `profile.protected.changed`,
`profile.pinned_tweet.changed`. Valid types are also
`profile.unavailable.changed`, `tweet.deleted`, `broadcast.started`,
`space.started`, `following.added`, `following.removed`, `follower.added`,
`follower.removed`, `profile.followers.changed`, `profile.following.changed`.

{"\n"}

Post monitor types are `post.reply.new`, `post.quote.new`,
`post.likes.changed`, `post.retweets.changed`, `post.replies.changed`,
`post.quotes.changed`, `post.bookmarks.changed`, `post.views.changed`,
`post.edited` & `post.deleted`.
A webhook takes up to 40 types.

## Integration handoff

Use this endpoint after you create a monitor. For an account monitor, call [`POST /monitors`](/api-reference/monitors/create). For a keyword monitor, call [`POST /monitors/keywords`](/api-reference/monitors/create-keyword). The webhook stores the HTTPS endpoint and event-type filter. Active monitors produce the events. Monitor billing includes webhook delivery.

{"\n"}

Store these fields right after creation.

<CardGroup cols={2}>

  <Card title="Webhook ID" icon="fingerprint">

    Store `id` for `POST /webhooks/{id}/test`, updates, deletes, and delivery
    lookups.

  </Card>
  <Card title="Delivery URL" icon="link">

    Store `url` to audit which queue, CRM, warehouse, or app endpoint receives
    monitor events.

  </Card>
  <Card title="Event filter" icon="funnel">

    Store `eventTypes`. Also keep the webhook filter aligned with the account or
    keyword monitor event types.

  </Card>
  <Card title="Signing secret" icon="shield-check">

    Store `secret` once and use it to verify `X-Xquik-Signature` on the raw
    request body.

  </Card>
  <Card title="Created at" icon="calendar-clock">

    Store `createdAt` for audit logs and later configuration checks.

  </Card>
  <Card title="Delivery payload" icon="webhook">

    Expect HTTPS `POST` bodies with `eventType`, `schemaVersion`, `deliveryId`,
    `streamEventId`, `occurredAt`, and `data`. Bodies also have `username` for
    account monitor events or `query` for keyword monitor events.

  </Card>
</CardGroup>

Every delivery includes `X-Xquik-Signature`, `X-Xquik-Timestamp`, and
`X-Xquik-Nonce` headers. Use `deliveryId` as the per-endpoint idempotency key.
Use `streamEventId` when you must process one monitor event once across retries
or endpoints.

Test the endpoint with [`POST /webhooks/{id}/test`](/api-reference/webhooks/test) before routing production events. Return a `2xx` response within 10 seconds. Process slow Slack, CRM, warehouse, or queue work afterward. Use [Signature Verification](/webhooks/verification) to validate the raw request body before processing.

## Response

### 201 Created

| Field           | Type       | Description                                                                                                                                                |
| --------------- | ---------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `id`            | `string`   | Unique webhook identifier.                                                                                                                                 |
| `url`           | `string`   | The registered delivery endpoint.                                                                                                                          |
| `eventTypes`    | `string[]` | Event types this webhook subscribes to.                                                                                                                    |
| `secret`        | `string`   | HMAC signing secret (64-character hex string). Xquik returns it only at creation. Store it in a secret manager.                                            |
| `createdAt`     | `string`   | ISO 8601 creation timestamp.                                                                                                                               |
| `ignoredFields` | `string[]` | Fields the request sent that this route does not read, in the order sent. They changed nothing. Omitted when the request sent only `url` and `eventTypes`. |

```json
{
  "id": "15",
  "url": "https://your-server.com/webhook",
  "eventTypes": ["tweet.new", "tweet.reply"],
  "secret": "a1b2c3d4e5f6a1b2c3d4e5f6a1b2c3d4e5f6a1b2c3d4e5f6a1b2c3d4e5f6a1b2",
  "createdAt": "2026-02-24T10:30:00.000Z"
}
```

<Warning>

The API returns `secret` once. Store it in a secret manager. You need it to [verify webhook signatures](/webhooks/verification). You cannot retrieve it again.

</Warning>

### 401 Unauthenticated

`{ "error": "unauthenticated", "message": "Missing or invalid API key" }`

{"\n"}

Missing or invalid API key or session cookie.

### 400 Invalid input

`{ "error": "invalid_input", "message": "Invalid URL or event types" }`

{"\n"}

Invalid URL (must be HTTPS) or empty `eventTypes` array.

### 429 Rate limited

Too many requests. Wait for the `Retry-After` header before retrying.

<Note>

This endpoint accepts 2 auth methods. Send an API key in the `x-api-key` header. Or send a session cookie from the dashboard.
