Run bulk data extractions from X in 5 stages. Check credits, estimate costs, run the job, retrieve JSON pages, and export files. This workflow scrapes tweets, exports followers, pulls tweet replies, saves files, or passes JSON. Files can be CSV, JSON, or XLSX. Paginated JSON can go to a CRM, warehouse, queue, or AI agent.

Use `reply_extractor` for reply authors and `follower_explorer` for profiles.
Jobs also cover posts, communities, lists, likes, reposts, quotes, and media.
Retrieve structured JSON or export CSV, JSON, or XLSX files.
Tweet search results can filter authors, dates, engagement, media, relationships, lists, and locations.

<section>

## Workflow overview

| Extraction stage | Exact API call                 | Durable checkpoint                                       |
| ---------------- | ------------------------------ | -------------------------------------------------------- |
| Check credits    | `GET /account`                 | Available balance                                        |
| Estimate results | `POST /extractions/estimate`   | `allowed`, `estimatedCost`, `estimatedResults`, `source` |
| Start scraping   | `POST /extractions`            | `id`, `toolType`, `status`                               |
| Retrieve rows    | `GET /extractions/{id}`        | `nextCursor` while `hasMore` is true                     |
| Export a file    | `GET /extractions/{id}/export` | Job ID, format, filename, destination                    |

<Info>

Treat `202 Accepted` as a queued run receipt. Xquik reserves credits after the job starts. Poll `GET /extractions/{id}` before handoff. The run can lower `resultsLimit` to the affordable count or fail with `insufficient_credits`.

</Info>

<Steps>

  <Step title="Check credits">

    Verify that your available credit balance can cover the job.

  </Step>
  <Step title="Estimate cost">

    Preview the extraction cost before committing. Check whether it fits within your remaining budget.

  </Step>
  <Step title="Run the extraction">

    Submit the extraction job, store the `202 Accepted` receipt, then poll before handoff.

  </Step>
  <Step title="Retrieve results">

    Paginate through extracted data via the API. Or export it as CSV, JSON, XLSX, Markdown, PDF, or TXT.

  </Step>
  <Step title="Export files">

    Download a file when the next tool expects one. Formats are CSV, JSON, XLSX, Markdown, PDF, or TXT.

  </Step>
</Steps>

## Step 1. Check credits

Before running an extraction, call [`GET /account`](/api-reference/account/get)
and store a small planning checkpoint.

```bash cURL
curl -s https://xquik.com/api/v1/account \
  -H "x-api-key: xq_YOUR_KEY_HERE" | jq
```

```json
{
  "checkpoint_type": "credit_check",
  "plan": "active",
  "credit_balance": "77000",
  "next_action": "estimate_extraction"
}
```

Store `plan` for billing context. Use `creditInfo.balance` to decide whether to
continue, top up, or lower `resultsLimit`. Decide before estimating the
extraction.

## Step 2. Estimate cost

Use the estimate endpoint first.
It shows expected rows and credits without charging you.

<CodeGroup>

```bash cURL
curl -X POST https://xquik.com/api/v1/extractions/estimate \
  -H "x-api-key: xq_YOUR_KEY_HERE" \
  -H "Content-Type: application/json" \
  -d '{
    "toolType": "reply_extractor",
    "targetTweetId": "2106061652617568263"
  }' | jq
```

```javascript Node.js
const estimate = await fetch("https://xquik.com/api/v1/extractions/estimate", {
  method: "POST",
  headers: {
    "x-api-key": "xq_YOUR_KEY_HERE",
    "Content-Type": "application/json",
  },
  body: JSON.stringify({
    toolType: "reply_extractor",
    targetTweetId: "2106061652617568263",
  }),
}).then((r) => r.json());

if (!estimate.allowed) {
  throw new Error(
    `Insufficient credits: need ${estimate.creditsRequired}, have ${estimate.creditsAvailable}`,
  );
}

console.log(`Estimated results: ${estimate.estimatedResults}`);
```

```python Python
estimate = requests.post(
    "https://xquik.com/api/v1/extractions/estimate",
    headers={"x-api-key": "xq_YOUR_KEY_HERE"},
    json={
        "toolType": "reply_extractor",
        "targetTweetId": "2106061652617568263",
    },
).json()

if not estimate["allowed"]:
    raise Exception(f"Insufficient credits: need {estimate['creditsRequired']}, have {estimate['creditsAvailable']}")

print(f"Estimated results: {estimate['estimatedResults']}")
```

</CodeGroup>

**Response.**

```json
{
  "allowed": true,
  "creditsRequired": "150",
  "creditsAvailable": "77000",
  "estimatedResults": 150,
  "source": "replyCount",
  "resolvedXUserId": "44196397"
}
```

The estimate reports these fields.

- `allowed`, `creditsRequired`, and `creditsAvailable` show affordability and balance.
- `source` and `estimatedResults` give the count basis and projected rows.
- `resolvedXUserId` is the ID returned by count-based profile estimates.

<Warning>

`allowed: false` means your balance cannot fund the full estimate. Add credits or lower `resultsLimit`.

</Warning>

<Tip>

`resultsLimit` defaults to `10,000` for estimates and jobs. Set any positive integer for a different bound. Billing follows unique emitted results. Source counts such as `followers` or `replyCount` can produce a smaller estimate.

</Tip>

</section>

## Step 3. Run the extraction

Submit the job with the same parameters you used for the estimate.

<CodeGroup>

```bash cURL
IDEMPOTENCY_KEY=$(uuidgen)
curl -X POST https://xquik.com/api/v1/extractions \
  -H "x-api-key: xq_YOUR_KEY_HERE" \
  -H "Idempotency-Key: $IDEMPOTENCY_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "toolType": "reply_extractor",
    "targetTweetId": "2106061652617568263"
  }' | jq
```

```javascript Node.js
const idempotencyKey = crypto.randomUUID();
const extraction = await fetch("https://xquik.com/api/v1/extractions", {
  method: "POST",
  headers: {
    "x-api-key": "xq_YOUR_KEY_HERE",
    "Idempotency-Key": idempotencyKey,
    "Content-Type": "application/json",
  },
  body: JSON.stringify({
    toolType: "reply_extractor",
    targetTweetId: "2106061652617568263",
  }),
}).then((r) => r.json());

console.log(`Job ${extraction.id}: ${extraction.status}`);
```

```python Python
from uuid import uuid4

extraction = requests.post(
    "https://xquik.com/api/v1/extractions",
    headers={"x-api-key": "xq_YOUR_KEY_HERE", "Idempotency-Key": str(uuid4())},
    json={
        "toolType": "reply_extractor",
        "targetTweetId": "2106061652617568263",
    },
).json()

print(f"Job {extraction['id']}: {extraction['status']}")
```

</CodeGroup>

**Response.**

```json
{
  "id": "a1b2c3d4-e5f6-7890-abcd-ef1234567890",
  "pollAfterMs": 1000,
  "statusUrl": "/api/v1/extractions/a1b2c3d4-e5f6-7890-abcd-ef1234567890",
  "waitUrl": "/api/v1/extractions/a1b2c3d4-e5f6-7890-abcd-ef1234567890?wait=10&limit=1&outputMode=compact",
  "toolType": "reply_extractor",
  "status": "running"
}
```

The endpoint returns `202 Accepted`. Save the key with the job ID. Reuse that
key only after a timeout or lost response. An exact retry returns the original
job with `Idempotency-Replayed: true`. A changed request returns `409`. A
terminal replay sets `pollAfterMs` to `0` and omits `Retry-After`.

</section>

### Search filters

`tweet_search_extractor` accepts every filter below. `community_search` accepts language, dates, media, verified authors, native reposts, and the listed minimums.
Omit unrequested filters. A minimum alone does not request `queryType=Top`.
Use `advancedQuery` only for a known X (Twitter) search operator string.

<CardGroup cols={2}>

  <Card title="Account filters" icon="at-sign">

    Use `fromUser` for author username and `toUser` for tweets directed to a
    user. Use `mentioning` for tweets that mention a user.

  </Card>
  <Card title="Date and language" icon="calendar-days">

    Use `language` for a language code such as `en`, `tr`, or `es`. Then bound
    the export with `sinceDate` and `untilDate` in `YYYY-MM-DD` format.

  </Card>
  <Card title="Media and engagement" icon="image">

    Use `mediaType` for `images`, `videos`, `gifs`, `media`, `links`, or `none`.
    Set `minFaves`, `minRetweets`, `minReplies`, or `minQuotes`.

  </Card>
  <Card title="Conversation filters" icon="message-circle">

    Use `replies`, `retweets`, and `quotes` with `include`, `exclude`, or `only`.
    Set `verifiedOnly` when only verified authors should match.

  </Card>
  <Card title="Query refinement" icon="sliders-horizontal">

    Combine `exactPhrase`, `excludeWords`, `anyWords`, `hashtags`, `cashtags`,
    and `url` for terms, entities, or linked domains.

  </Card>
  <Card title="Tweet relationships" icon="git-branch">

    Use `conversationId`, `inReplyToTweetId`, `quotesOfTweetId`, or
    `retweetsOfTweetId` for one conversation or source tweet.

  </Card>
  <Card title="List and location scopes" icon="map-pin">

    Use `listId`, `place`, `placeCountry`, `pointRadius`, or `boundingBox`.
    These fields narrow search results to a list or location.

  </Card>
  <Card title="Advanced query" icon="code">

    Use `advancedQuery` only for raw X (Twitter) search syntax.
    Prefer the 30 structured fields when one already represents the filter.

  </Card>
</CardGroup>

```bash cURL

  -H "Idempotency-Key: $(uuidgen)" \
  -H "Content-Type: application/json" \
  -d '{
    "toolType": "tweet_search_extractor",
    "searchQuery": "artificial intelligence",
    "language": "en",
    "mediaType": "images",
    "minFaves": 100,
    "sinceDate": "2026-03-06",
    "untilDate": "2026-03-13",
    "retweets": "exclude"
  }' | jq
```

## Twitter scraper API questions

### What is a Twitter scraper API?

A Twitter scraper API collects X posts and profiles through documented requests.
Xquik creates a job, returns its ID, and exposes cursor-based JSON results.
It can also generate downloadable files.
This Twitter data scraper covers tweets, replies, followers, following, communities, and lists.
It also covers spaces, likes, reposts, quotes, and media posts.

### Can Python scrape Twitter without the official API?

Yes, through Xquik's REST API and the Python examples above.
API access still requires an [Xquik API key](/x-api-quickstart).
You do not need to maintain an X developer application.
Poll the job, follow every cursor, and save structured tweet or profile rows.

### How do I export Twitter followers?

Run `follower_explorer` with the Twitter account username in `targetUsername`.
This Twitter follower scraper returns visible follower profiles.
Estimate the job before creating it.
Then poll every JSON page or download a file.
The follower export API keeps each Twitter profile ID, username, counts, and verification.
It also keeps names when available.

### How do I export tweet replies?

Use `reply_extractor` with `targetTweetId` for visible reply-author profiles.
Use `tweet_search_extractor` when the reply posts themselves matter.
Pass `inReplyToTweetId` to restrict results to one source tweet.
A tweet replies export can use CSV, JSON, XLSX, or paginated JSON.
Store the source tweet ID, extraction ID, row IDs, and cursor checkpoint.

### Why use a Twitter scrape API instead of a custom web scraper?

A custom web scraper must maintain selectors, login behavior, retries, and parsers.
A Twitter scrape API uses documented requests, statuses, cursors, and output fields.

## Error handling

<CardGroup cols={2}>

  <Card title="Resolve billing access" icon="credit-card">

    A `402` means the account cannot fund this extraction. Check the available
    balance and `payment_options`. You need no active plan when enough
    credits remain.

  </Card>
  <Card title="Top up credits" icon="coins">

    `402 insufficient_credits` means the account cannot cover the requested
    extraction. Top up credits, wait for the next grant, or lower `resultsLimit`.

  </Card>
  <Card title="Fix toolType" icon="list-checks">

    `400 invalid_tool_type` means `toolType` is not one of the supported
    extraction tools. Check the [tool types](#tool-types-reference) reference.

  </Card>
  <Card title="Fix required fields" icon="wrench">

    `400 invalid_input` usually means the target field is missing or malformed.
    Match `targetTweetId`, `targetUsername`, `targetCommunityId`,
    `targetListId`, `targetSpaceId`, or `searchQuery` to the selected tool.

  </Card>
  <Card title="Retry read service" icon="refresh-cw">

    `502 x_api_unavailable` means the read service is temporarily unavailable.
    Retry with exponential backoff, then contact support if the error persists.

  </Card>
</CardGroup>
