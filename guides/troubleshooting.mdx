## Error codes

### 401 Unauthenticated

The API key or OAuth token is missing, invalid, expired, or revoked. Check the
following items.

- **API key header.** Send `x-api-key: xq_...` or `Authorization: `<span className="cn"><wbr />`Bearer xq_...`</span>.
- **OAuth header.** Send `Authorization: `<span className="cn"><wbr />`Bearer <access_token>`</span>. OAuth clients normally manage this automatically.
- **Key format.** Must start with `xq_`. If it doesn't, you're using the wrong value.
- **Key revoked.** Revoked keys return <span className="nw">401 immediately</span>. Generate a new key from the dashboard.
- **OAuth token expired.** Let the MCP client refresh the token. Reconnect Xquik if refresh fails.
- **API key management auth.** Listing, creating, pausing, and revoking keys require a <span className="nw">same-origin</span> dashboard session. API keys and OAuth bearer tokens cannot manage keys.

```bash
# Correct
curl https://xquik.com/api/v1/account \
  -H "x-api-key: xq_your_api_key_here"

# Wrong - missing header
curl https://xquik.com/api/v1/account
```

### 403 paused API key

`api_key_paused` means this key is paused. Resume it on the
[API keys page](https://dashboard.xquik.com/en/api-keys), and the next request goes through. Pausing
never deletes the key or its settings.

### 403 insufficient scope

`insufficient_scope` means the key lacks a scope this route needs. `requiredScope` names it.
Add it on the [API keys page](https://dashboard.xquik.com/en/api-keys), then retry.

### 403 IP not allowed

`ip_not_allowed` means the key has an IP allowlist without the calling IP. The message names that IP.
Add it on the [API keys page](https://dashboard.xquik.com/en/api-keys), or call from a listed IP.
An empty list allows any IP.

### 401 authentication or 402 payment required

Anonymous non-MPP paid reads return `401` with a Bearer challenge and guest wallet action. Direct MPP reads return `402` with a Payment challenge and the same action. Account or guest credit failures also return `402`. The failed request creates no checkout.

{"\n"}

Try these fixes.

- For account keys, check `GET /api/v1/account` and use only the advertised account payment action
- For guest keys, check [guest wallet status](/api-reference/guest-wallets/status). Then use only the advertised guest <span className="nw">top-up</span> action
- For the direct MPP operations, complete the MPP challenge. You can also ask the user to confirm a guest wallet amount
- For the other <span className="nw">guest-eligible</span> reads, authenticate. You can also ask the user to confirm a guest wallet amount
- Use [Estimate Extraction](/api-reference/extractions/twitter-scraping-cost-estimator) to see the credit cost before running extractions

Ask the user to choose an option and amount before creating checkout. Never trigger checkout, top-up, or subscription automatically after `401` or `402`.

### Monitor credits

Monitor slots are unlimited. Active monitors cost 30 credits per hour. They
require available credits while enabled.

```json
{ "error": "insufficient_credits", "message": "Insufficient credits" }
```

Try these fixes.

- Pause an unused account monitor with `PATCH /api/v1/`<span className="cn"><wbr />`monitors/{id}`</span> and `{ `<span className="cn"><wbr />`"isActive": false }`</span>
- Pause an unused keyword monitor with `PATCH /api/v1/`<span className="cn"><wbr />`monitors/`<wbr />`keywords/{id}`</span> and `{ `<span className="cn"><wbr />`"isActive": false }`</span>
- Delete an unused monitor. Poll the returned `statusUrl` until it returns `404`.
- Check current monitor billing with `GET /api/v1/account`, which shows `monitorsUsed` and `monitorBilling`

### 403 API key budget reached

The call doesn't fit what's left of the key's monthly credit budget. It never ran and cost nothing. A read with a `limit` needs that many results' price left. A write needs its price plus 20 credits left. Other keys on the account keep working.

```json
{
  "error": "api_key_budget_reached",
  "message": "This API key reached its monthly credit budget. Raise or remove it at dashboard.xquik.com/api-keys, or wait for the next UTC month."
}
```

Try these fixes.

- Raise or remove `monthlyBudgetCredits` with [Update API key](/api-reference/api-keys/update). The next call works.
- Wait for the next UTC month, when the key's spend starts again at 0.
- Compare `monthlySpentCredits` across keys with [List API keys](/api-reference/api-keys/list) to find unexpected usage.

### 429 Too many requests

You've exceeded the API rate limit. The API uses fixed windows per tier.

<CardGroup cols={2}>

  <Card title="Read" icon="database">

    `GET`, `HEAD`, and `OPTIONS` share 500 requests per 1 second.

  </Card>
  <Card title="Change" icon="pen-line">

    Other methods on Xquik resources share 6,000 requests per 60 seconds.

  </Card>
  <Card title="X action" icon="send">

    Actions through a connected X (Twitter) account share 120 requests per 60 seconds.

  </Card>
</CardGroup>

Try these fixes.

- Respect `Retry-After`. Otherwise start at <span className="nw">1 second</span>, add jitter, and stop after <span className="nw">3 retries</span>.
- Requests sent before the fixed window resets keep returning <span className="nw">`429` until</span> `Retry-After` elapses.
- Check the `Retry-After` header for the <span className="nw">server-recommended</span> wait time.
- Use webhooks instead of polling. They push detected events without repeated <span className="nw">event-list</span> calls.
- Batch your logic. Fetch events once per minute instead of once per second.

See the [Rate Limits](/guides/rate-limits) guide for backoff code examples.

### 502/503 Read service busy or unavailable

The read service is temporarily unavailable or busy. This is usually transient.

Try these fixes.

- Respect `Retry-After` when present, then retry the request
- If no `Retry-After` header is present, retry after <span className="nw">5 to</span> <span className="nw">10 seconds</span>
- Use exponential backoff (see [Error Handling](/guides/error-handling))
- After <span className="nw">5 minutes</span> of errors, the read service may have an outage

The same applies to draws. So do tweet, profile, follower, reply, timeline, community and list endpoints under `/api/v1/x/*`.

## Common questions

### Webhooks not arriving?

Webhook delivery can fail without a visible error. Check each item.

1. **Webhook is active.** Verify `isActive: true` and `deliveryStatus: `<span className="cn"><wbr />`"active"`</span> via `GET /api/v1/webhooks`. Paused webhooks do not receive deliveries.
2. **HTTPS required.** Xquik rejects HTTP endpoints. Your URL must start with `https://`.
3. **Response time.** Respond with `2xx` within <span className="nw">10 seconds</span>, even for events you skip. Slower responses and rejections count as failures. A failure can delay new deliveries by up to <span className="nw">15 minutes</span>.
4. **Check deliveries.** Call `GET /api/v1/`<span className="cn"><wbr />`webhooks/`<wbr />`{id}/`<wbr />`deliveries`</span> to see delivery status, attempt count, and error messages.
5. **Correlate source events.** Call `GET `<span className="cn"><wbr />`/api/v1/events/{id}`</span> with the stored `streamEventId`.
6. **Local testing.** If using ngrok or a tunnel, verify it's running and the URL is current. Ngrok URLs change on restart (free plan).
7. **Needs attention.** `needs_attention` means <span className="nw">200 failed</span> checks in a row. Xquik keeps retrying. Fix the receiver, then call `POST /api/v1/`<span className="cn"><wbr />`webhooks/`<wbr />`{id}/`<wbr />`resume`</span>. It starts sending waiting deliveries at once.
8. **Event type mismatch.** Your webhook must subscribe to the event types your monitors produce. A webhook listening for `tweet.new` won't receive `tweet.reply` events.

> **Tip.** See the [Webhook Testing](/guides/twitter-webhook-testing) guide for a step-by-step local setup with ngrok.

### Monitor not tracking events?

If your monitor is active but no events appear, check these items.

- **Check `isActive`.** Confirm via `GET /api/v1/`<span className="cn"><wbr />`monitors/{id}`</span> that `isActive` is `true`. Paused monitors don't track.
- **Event propagation delay.** Events take seconds to minutes to appear depending on X API latency. This is normal.
- **Event types.** Verify your monitor's `eventTypes` array includes the type you expect. A monitor tracking only `["tweet.new"]` won't capture replies or retweets.
- **Account activity.** The monitored X account must post content matching your event types. No posts means no events.
- **Pagination.** If listing events, check `hasMore` in the response. Older events may be on subsequent pages.

### How do I replay stored monitor events?

Call `GET /api/v1/`<span className="cn"><wbr />`events?`<wbr />`monitorId=`<wbr />`{id}&`<wbr />`limit=50`</span> for account monitors, or
`GET /api/v1/`<span className="cn"><wbr />`events?`<wbr />`keywordMonitorId=`<wbr />`{id}&`<wbr />`limit=50`</span> for keyword monitors. Then
process each event once. If `hasMore` is `true`, store `nextCursor` and pass it as `cursor` next time. Add `eventType` when you need to separate tweets, replies, quotes, or profile changes.

### Write action still pending?

Inspect the durable action returned by the write.

- Store `id`, `request.hash`, `account`, `target`, `billing`, and `statusUrl`
- Poll `statusUrl` while `terminal` is `false`
- Respect `Retry-After`, `pollAfterMs`, and `nextAction`
- Retry only when `safeToRetry` is `true`, using a new `Idempotency-Key`
- Verify the result before retrying when `nextAction.type` is `verify_result`

### How do I check my usage?

Call `GET /api/v1/account`. The `creditInfo` object shows your balance.

```json
{
  "creditInfo": {
    "balance": "42500",
    "lifetimePurchased": "140000",
    "lifetimeUsed": "97500",
    "autoTopupEnabled": false
  }
}
```

- `creditInfo.balance` shows the remaining credits available for metered calls
- At a `balance` of `0`, Xquik rejects metered calls. A credit <span className="nw">top-up</span> or an auto <span className="nw">top-up</span> ends that
- Auto <span className="nw">top-up</span> stops after <span className="nw">3 declined</span> charges in a row. Update your card in the dashboard to restart it.
- With exchange rates over <span className="nw">3 ECB</span> working days old, <span className="nw">non-USD</span> auto <span className="nw">top-ups</span> skip. Nothing is charged.

The dashboard billing page also charts usage.

{"\n"}

See [Billing & Usage](/guides/billing) for credit costs and billing.

### Can I use the API without a subscription?

Yes. Full account metered operations work while enough available credits remain. Choose the access boundary.

- **Guest wallet.** Prepay the eligible <span className="nw">paid-read</span> routes through a confirmed USD <span className="nw">10 to</span> <span className="nw">250 hosted</span> checkout.
- **MPP.** Pay per request on <span className="nw">fixed-price</span> GET operations without an account or API key.
- **Full account.** Use available account credits for writes, monitors, extractions, draws, and <span className="nw">connected-account</span> reads. Webhooks and account management are free.

Subscribe for monthly credits or top up from the [dashboard billing page](https://dashboard.xquik.com/en/account?tab=subscription). Remaining credits stay usable after a plan ends.

### How do I connect an AI agent?

Xquik has 2 MCP servers. Choose based on what the agent needs to do.

<CardGroup cols={2}>

  <Card title="Search docs" icon="book-open">

    Connect `https://`<span className="cn"><wbr />`docs.`<wbr />`xquik.com/mcp`</span>. It is read-only and requires no auth.

  </Card>
  <Card title="Run API actions" icon="terminal">

    Connect `https://`<span className="cn"><wbr />`xquik.com/mcp`</span>. Full credentials expose every JSON or text route. Guest `paid_reads` keys expose the eligible paid-read routes.

  </Card>
</CardGroup>

Follow these setup steps.

1. For docs search, add `https://`<span className="cn"><wbr />`docs.`<wbr />`xquik.com/mcp`</span>.
2. For account actions, use a full API key or OAuth login. Prefer OAuth when the client supports browser authorization.
3. For guest reads, activate a guest key through direct REST. Then authenticate MCP with that key.

Guest wallet creation, status, and top-up are never executable through MCP.

These are the current client paths.

- **OAuth 2.1.** Claude.ai, Claude Desktop, Claude Code, ChatGPT, Cursor, VS Code, Windsurf, and OpenCode. Gemini CLI, GitHub Copilot CLI, Cline and Qwen Code also use it. So do Pi, Goose and Codex CLI
- **<span className="nw">API-key</span> only.** Roo Code's archived final release has no MCP OAuth provider
- **Older Pi.** Builds without `pi mcp` require an upgrade or a tested adapter

See [Docs MCP server](/mcp/docs-mcp) for docs search. See [MCP Server overview](/mcp/overview) for account actions. The [MCP Tools](/mcp/tools) reference has the tool details.

### MCP OAuth does not open or shows an unknown application

Use this checklist.

1. Enter `https://`<span className="cn"><wbr />`xquik.com/mcp`</span> as the exact server URL.
2. Remove any manually entered client ID or client secret unless your client requires preregistration.
3. Remove and <span className="nw">re-add</span> the connector to restart OAuth discovery.
4. Start login from the MCP client. Do not open `/api/auth/google` directly.
5. Allow the browser to return to the client's exact callback URL.

Xquik publishes all required discovery documents.

- Protected resource metadata is at `https://`<span className="cn"><wbr />`xquik.`<wbr />`com/.`<wbr /><span className="nw">`well-known/`</span><wbr /><span className="nw">`oauth-protected-resource/`</span><wbr />`mcp`</span>
- Authorization server metadata is at `https://`<span className="cn"><wbr />`xquik.`<wbr />`com/.`<wbr /><span className="nw">`well-known/`</span><wbr /><span className="nw">`oauth-authorization-server`</span></span>
- The <span className="nw">agent-readable</span> auth guide is at `https://`<span className="cn"><wbr />`xquik.com/`<wbr />`auth.md`</span>

Xquik supports CIMD and DCR. Let the client use its documented registration
flow. Claude selects CIMD when authorization metadata advertises support and the
public `none` authentication method. Otherwise it can use DCR. ChatGPT app
creators choose CIMD or DCR during setup. If a URL-form `client_id` fails, check
its public HTTPS metadata URL. It must include an explicit path. A trailing `/`
is sufficient. It must return JSON without a redirect. Repeat the exact URL in
`client_id`. List the callback in `redirect_uris`.

### How do I export extraction results?

Call `GET /api/v1/`<span className="cn"><wbr />`extractions/`<wbr />`{id}/`<wbr />`export?`<wbr />`format=csv`</span>. Other formats are `json`, `xlsx`, `md`, `md-document`, `pdf`, and `txt`. The response is a file download.

Exports work like this.

- Exports include every row. A PDF above <span className="nw">10,000 rows</span> comes as a ZIP of PDF parts
- Available formats are CSV, JSON, Markdown, Markdown Document, PDF, TXT, and XLSX

See [Export Extraction](/api-reference/extractions/export) for column details and code examples.
