## Codex

Current Codex supports Xquik OAuth with the shared local MCP configuration:

```bash
codex mcp add xquik --url https://xquik.com/mcp
codex mcp login xquik
codex mcp list
```

Complete sign-in & authorization in your browser.
The CLI, app & IDE extension share the host's MCP configuration.
See [OpenAI setup](/mcp/overview#openai) & [Codex MCP](https://learn.chatgpt.com/docs/extend/mcp).
For API keys, use [environment-backed authentication](/mcp/overview#codex-api-key-authentication).

## Claude Code

Add Xquik to your user configuration:

```bash
claude mcp add --scope user --transport http xquik https://xquik.com/mcp
claude mcp login xquik
claude mcp list
```

Use `--scope project` to share the URL through `.mcp.json`.
Claude Code asks you to approve project servers before connecting.
Use `/mcp` inside a session to authenticate or reconnect.

Version 2.1.286 fixes stale MCP discovery & repeated authentication reminders.
It also fixes credential redaction in MCP errors.
Upgrade before diagnosing those symptoms.
Version 2.1.287 keeps managed permissions for all MCP tool names.

Xquik supports automatic registration. Leave client ID & client secret unset.
For API-key headers, `.mcp.json` expands `${XQUIK_API_KEY}` from your environment.
See [Claude Code MCP](https://code.claude.com/docs/en/mcp).

## Cursor

Keep the existing URL entry in `~/.cursor/mcp.json` or `.cursor/mcp.json`:

```json
{
  "mcpServers": {
    "xquik": {
      "url": "https://xquik.com/mcp"
    }
  }
}
```

Current [Cursor CLI docs](https://cursor.com/docs/cli/mcp) use the `agent` command:

```bash
agent mcp login xquik
agent mcp list
```

Approve the server when prompted. Team distribution does not automatically enable it.
Enterprise policy may restrict servers.
Xquik needs no static OAuth `auth` object.
API-key headers use `${env:XQUIK_API_KEY}`.
Remote entries cannot load `envFile`.
See [Cursor MCP configuration](https://cursor.com/docs/mcp).

## OpenCode

Add this entry to `opencode.json`:

```json
{
  "$schema": "https://opencode.ai/config.json",
  "mcp": {
    "xquik": {
      "type": "remote",
      "url": "https://xquik.com/mcp"
    }
  }
}
```

Then authenticate & check discovery:

```bash
opencode mcp auth xquik
opencode mcp list
```

OpenCode automatically registers the client & refreshes OAuth tokens.
For connection failures, run `opencode mcp debug xquik`.
An API-key entry needs `"oauth": false` & `Bearer {env:XQUIK_API_KEY}`.
See [OpenCode MCP servers](https://opencode.ai/docs/mcp-servers/).

## Pi

Pi 1.0.0 has native MCP. No community adapter is required.
If your build lacks `pi mcp`, run `pi update self` before setup.

```bash
pi mcp add xquik --url https://xquik.com/mcp
pi mcp login xquik
pi mcp list
```

Pi stores global servers in `~/.pi/agent/mcp.json`.
Use `--local` for `.pi/mcp.json`; project trust is required.
Pi supports Streamable HTTP, not legacy SSE.
Use `/mcp` to inspect connections & `/reload` after changing external configuration.
Pi 1.0.0 validates OAuth callback issuers & stores credentials per server name & URL.
Different server names at the same URL need separate sign-ins.

Pi's default `codemode` exposure makes tools available through tool search & scripts.
Use `--exposure direct` when adding Xquik to expose its 3 tools directly.
Pi's exposure setting is separate from Xquik's [tool mode](/mcp/overview#choose-a-tool-mode).

For an environment-backed API key:

```bash
pi mcp add xquik --url https://xquik.com/mcp --bearer-token-env-var XQUIK_API_KEY
```

Set `XQUIK_API_KEY` before starting Pi. This replaces OAuth for that entry.
See [Pi's MCP guide](https://github.com/earendil-works/pi/blob/v1.0.0/packages/coding-agent/docs/mcp.md).

## Copilot CLI, Gemini CLI, Cline & Qwen Code

Current Copilot CLI uses this command:

```bash
copilot mcp add --transport http xquik https://xquik.com/mcp
```

The URL is positional. Use `/mcp` to inspect the server & complete authentication.
Version 1.0.90 improves discovery recovery & cached OAuth token reuse.
See [Copilot CLI MCP setup](https://docs.github.com/en/copilot/how-tos/copilot-cli/customize-copilot/add-mcp-servers).

Gemini CLI & Qwen Code retain `httpUrl` for manual Streamable HTTP entries:

```json
{
  "mcpServers": {
    "xquik": {
      "httpUrl": "https://xquik.com/mcp"
    }
  }
}
```

Gemini uses `~/.gemini/settings.json`; Qwen uses `~/.qwen/settings.json`.
Use their `/mcp` authentication flow after adding the server.
See [Gemini MCP](https://geminicli.com/docs/tools/mcp-server/)
& [Qwen MCP](https://qwenlm.github.io/qwen-code-docs/en/users/features/mcp/).

Cline CLI uses `cline mcp` to manage servers & OAuth.
Its extension uses the MCP Servers panel.
Choose Streamable HTTP & enter `https://xquik.com/mcp`.
The CLI, extension & Desktop app have separate release versions.
See [Cline MCP](https://docs.cline.bot/mcp/mcp-overview).

## VS Code

Current VS Code recommends portable `.mcp.json` for new project servers:

{
  "mcpServers": {
    "xquik": {
      "type": "http",
      "url": "https://xquik.com/mcp"

  }

Run **MCP: Add Server** for guided setup, then approve server trust & OAuth.
Managed MCP policies may restrict access.
See [VS Code MCP setup](https://code.visualstudio.com/docs/agent-customization/mcp-servers).

## Windsurf / Devin Desktop

Current Windsurf documentation calls the editor Devin Desktop.
Choose the guide for your active agent.

For Devin Local, run:

```bash
devin mcp add xquik https://xquik.com/mcp
devin mcp login xquik
devin mcp list
```

Current Devin CLI stores servers in dedicated `mcp_config.json` files.
The default local file is `.devin/mcp_config.local.json`.
Use `--scope user` for your global configuration.
See [Devin MCP configuration](https://docs.devin.ai/cli/extensibility/mcp/configuration).

Legacy Cascade uses `mcp_config.json` with `mcpServers` & `serverUrl`.
Open that file through Cascade's MCP menu to find your installed version's location.
Current macOS & Linux releases use `~/.config/devin/mcp_config.json`.
Older Windsurf releases used `~/.codeium/windsurf/mcp_config.json`.
Cascade allows 100 enabled tools total, so prefer Xquik's default Code Mode.
See [Cascade MCP configuration](https://docs.devin.ai/desktop/cascade/mcp).

## Goose & Roo Code

Current 1.52.0 retains that fix.

```bash
goose session --with-streamable-http-extension https://xquik.com/mcp
```

See [Goose extensions](https://goose-docs.ai/docs/getting-started/using-extensions/)

Roo Code is archived. Its final release supports HTTP headers without MCP OAuth.
Use its [environment-backed API-key configuration](/mcp/overview#remaining-api-key-and-adapter-paths).

## Check the connection

Confirm the server connects & lists `docs`, `search` & `execute`.
Those are Xquik's default Code Mode tools.
Native mode at `?codemode=false` exposes individual operations instead.

Use `xquik-docs` as a separate entry for `https://docs.xquik.com/mcp`.
That server needs no OAuth & searches public documentation.
A successful Docs MCP connection does not authorize API MCP.
See [Docs MCP setup](/mcp/docs-mcp).

OAuth connections need browser login & consent in each client.
Do not copy another client's token store.
For a `401`, use the client's authentication flow.
For issuer errors, upgrade the affected client before retrying.
Include the UTC time & `X-Request-Id` when [reporting a connection failure](/guides/troubleshooting).
