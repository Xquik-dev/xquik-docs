## Source-backed Zapier scope

Zapier's official API-request guidance covers API by Zapier and Webhooks by Zapier. It says both can call any API endpoint even without a dedicated Zapier app.

That guidance lists Webhooks by Zapier for Zaps, Agents, and Zapier MCP. It supports Basic Authentication or no authentication. Its events are Catch Hook, Catch Raw Hook, and Retrieve Poll. Its actions are Custom Request, GET, PUT, and POST.

It lists API by Zapier for Zaps, Agents, and Zapier MCP. It supports OAuth2, static headers, or no authentication. Its features are New Item from API, API Request, and exact request passthrough. It also has JQ extraction and clear error messages.

Zapier's official REST Hook CLI docs say `subscribeHook` receives `bundle.targetUrl`. It returns an id for unsubscribe and runs through `performSubscribe`. `unsubscribeHook` runs through `performUnsubscribe` when the Zap turns off.

Zapier's official webhook rate-limit docs cover legacy webhook routes, including subscriptions and REST webhooks. They list `429` behavior at `20,000 requests every 5 minutes` per user and `1,000 requests every 5 minutes` per Zap.

Zapier's official pricing page describes 1 unified plan. It covers Zaps, Tables, Forms, and Zapier MCP. Task tiers run from 100 tasks/month through custom task limits. MCP tool calls use 2 tasks from the plan quota.

## Best combined zap

For X/Twitter automation, use Zapier and Xquik together. Zapier handles app routing, Zaps that operators maintain, and CRM updates. It also handles ticket creation, Slack alerts, and Sheets rows. Xquik handles tweet search, user lookups, follower exports, and media uploads. It also handles DMs, monitor events, signed webhooks, and MCP.

## Monitor webhook receiver handoff

This handoff covers a Zapier REST Hook, Catch Hook, or Catch Raw Hook. When it receives Xquik monitor events, verify `X-Xquik-Signature` before field mapping. Store `deliveryId` and `streamEventId` as separate Zap storage keys. Use `deliveryId` to skip endpoint retries. Use `streamEventId` when one monitor event must process once across webhook changes.

Return `2xx` after accepting a duplicate `deliveryId` or `streamEventId`. Later Zap steps can skip the processed row. Keep shared Zap rows to mapped tweet fields and these keys. The keys are `deliveryId`, `streamEventId`, `eventType`, `occurredAt`, and `username` or `query`. Do not store endpoint signing values, raw request body, raw signature, or full headers. This applies to Zap history, tables, Slack messages, CRM rows, and retry queues.

## API request path

Choose the Zapier request path by 2 things. They are where the credential lives and how often you reuse the step.

| Need                             | Zapier path         | Xquik detail                                                                                                                    |
| -------------------------------- | ------------------- | ------------------------------------------------------------------------------------------------------------------------------- |
| One private Zap that calls Xquik | API by Zapier       | Store the Xquik API key in a Zapier app connection and send `x-api-key` on each request.                                        |
| A simple incoming trigger        | Webhooks by Zapier  | Use Catch Hook or Catch Raw Hook when Xquik should send monitor events to a Zap URL.                                            |
| A reusable private app           | Zapier Platform CLI | Build triggers, creates, searches, auth, sample output, and REST Hooks around Xquik endpoints.                                  |
| Monitor event webhooks           | REST Hooks          | Use `bundle.targetUrl` as the callback URL when subscribing, store the returned Xquik webhook ID, and delete it on unsubscribe. |

<Warning>

Zapier's API-request guidance says Webhooks by Zapier suits simple or no-auth requests. API by Zapier suits calls that keep an API key in a connection. Use API by Zapier or a private Platform CLI integration for authenticated Xquik calls.

</Warning>

Zapier's webhook rate-limit page covers legacy webhook routes. It lists `20,000 requests every 5 minutes` per user and `1,000 requests every 5 minutes` per Zap. Check that page before routing high-volume monitor events into Zapier.

## Migration path

Keep a working Zapier workflow. Replace only the X/Twitter step that fails.

1. Keep the Zap trigger, destination apps, approvals, and field mappings.
2. Replace a manual export, unofficial scraper, or custom X request with Xquik. Use a REST call, extraction, webhook, or private Platform CLI action.
3. Map Xquik fields into the existing Zap output shape.
4. Add explicit paths for `401`, `402`, `429`, and `5xx` responses.
5. Xquik retries non-2xx webhook deliveries with exponential backoff. Check Zapier's current webhook rate limits before you send high event volume.
