## Source-backed TweetStream scope

TweetStream's official home describes it as a Twitter WebSocket API for crypto traders. It says the API streams structured JSON for tracked accounts.

The home page says teams connect a live feed. They track accounts with keyword filters and receive alerts. Alerts can include OCR text, detected crypto assets, live prices, and Polymarket detection.

TweetStream's pricing page shows a Basic annual plan at USD 139/month billed annually. It has 3 WebSocket connections and 50 monitored X/Twitter accounts. The Elite annual plan costs USD 349/month billed annually. It has 10 WebSocket connections and 250 monitored accounts.

Other TweetStream docs and guides give monthly prices. They describe monthly Basic pricing from USD 199/month and Elite pricing at USD 499/month. Validate monthly and annual pricing at checkout before buying.

The quickstart lists the WebSocket endpoint as `wss://ws.tweetstream.io/ws`, protocol `tweetstream.v1`, and an auth subprotocol. It also covers environments that cannot set the auth subprotocol. For those, the server accepts Bearer auth headers and query parameters.

TweetStream's WebSocket envelope uses `v`, `t`, `op`, `ts`, and `d`. The message family `t` can be `tweet`, `account`, or `control`. Operations include `content`, `meta`, `update`, `delete`, `profile_update`, `follow`, `auth_ping`, `auth_pong`, and `twitter_handles_result`.

Payload docs say tweet events send a `content` message first. They also send optional `update` messages and a `meta` message when enrichment is ready. Tweet payloads include `tweetId`, `text`, `createdAt`, `author`, optional `link`, optional `media`, and optional `ref`.

TweetStream account events include profile updates and follow notifications. Profile changes can include avatar, banner, bio, handle, location, and name.

The `meta` payload can add source markers for text or OCR. It can include OCR text and detected crypto assets, centralized-exchange markets, and prediction markets.

The history API returns rows. They hold `tweetId`, `body`, `time`, `receivedTime`, `link`, `messageType`, `twitterHandle`, `twitterId`, `content`, and optional `meta`.

## Migration path

Start with one API-backed task. Compare output shape, latency, pagination, retries, exports, and alert delivery in Xquik. Keep the current integration running during that comparison.

Keep the test small. Use 1 task, 1 output, 1 cost model, and 1 owner for the output. Switch only when the Xquik output matches the required records. It must also reduce integration work or cost.

Compare TweetStream and Xquik by stream latency and enrichment needs. Also compare REST endpoint count and export needs.

Price the real workload. On Xquik, Starter is USD 20/month with 140,000 credits. Top-ups are USD 0.00015/credit. Webhook and stored-event management cost no credits. Active monitors bill only while enabled.
