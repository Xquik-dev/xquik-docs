## Source-backed n8n scope

n8n's official X node docs list built-in operations for direct messages and tweets. For tweets, they cover creating or replying, deleting, searching, liking, and retweeting. Other operations get users and add list members.

n8n's official X node docs say the node also works as an AI tool. In that mode, n8n sets parameters automatically or from AI-directed information.

n8n's official HTTP Request node docs describe REST calls. The calls can reach any app or service with a REST API. The docs cover generic credential methods. They list query parameters, headers, and form, form-data, JSON, binary-file, and raw request bodies. They also cover response formatting, full response headers and status, and batching. They cover pagination, timeout, and cURL import as well.

n8n's official executions docs cover Cloud and self-hosted plans other than Community Edition. They say these plans count production executions started automatically by triggers, schedules, or polling. Quota counting excludes manual executions.

n8n's official Community Edition docs say that edition includes almost the complete feature set. They then list features the unregistered Community Edition lacks. Examples are projects, sharing, external credential storage, log streaming, and multi-main mode. Other examples are SSO and Git version control.

## Best combined workflow

Use n8n and Xquik together. n8n handles triggers, approvals, schedules, and destination apps. Xquik handles tweet search, follower exports, write actions, exports, event delivery, and MCP.

<CardGroup cols={1}>

  <Card title="Setup" icon="route">

    In n8n, you create workflow triggers and destination app credentials. In Xquik, you create one API key or MCP credential.

  </Card>
  <Card title="Output" icon="download">

    n8n routes transformed workflow items. Xquik returns tweet records, user records, exports, monitor events, and webhook payloads.

  </Card>
  <Card title="Handoff" icon="workflow">

    n8n sends results to CRMs, Slack, Sheets, queues, or databases. Xquik supplies REST, signed webhooks, SDKs, exports, and MCP tools.

  </Card>
</CardGroup>

## Xquik workflows to run from n8n

Use Xquik inside n8n when the workflow needs an X data or action step. That step runs before the workflow routes data to other apps.

<CardGroup cols={2}>

  <Card title="Tweet search to CRM" icon="database">

    Call `GET /x/tweets/search` and filter by engagement or author. Then send matching records to a CRM, spreadsheet, queue, or Slack channel.

  </Card>
  <Card title="Follower export to sheets" icon="sheet">

    Create an extraction job and poll until `completed`. Then append follower, following, list, community, or Space rows to Google Sheets.

  </Card>
  <Card title="Monitor events to workflow" icon="webhook">

    Receive signed Xquik webhook payloads for account or keyword monitors. Then branch by event type, author, text, or engagement fields.

  </Card>
  <Card title="AI agent research" icon="bot">

    Connect n8n AI Agent workflows to the Xquik MCP server. Use it for tweet search, user lookups, trends, extraction planning, and source links.

  </Card>
</CardGroup>

## Trial checklist

<Steps>

  <Step title="Pick one X task">

    Use 1 task, such as tweet search, follower export, or a monitor alert. A media upload, DM send, or AI research also works.

  </Step>
  <Step title="Run it in n8n">

    Build the n8n trigger and the Xquik HTTP Request or MCP step. Also build the data transform and destination app step.

  </Step>
  <Step title="Inspect the Xquik output">

    Confirm returned fields, pagination, and `Retry-After` handling. Also confirm webhook signature verification, export format, and field mapping in later nodes.

  </Step>
  <Step title="Price the real workload">

    Compare n8n workflow executions and hosting or plan needs. Include Xquik credits, active monitor billing, and engineering time for retries and alerts.

  </Step>
</Steps>

## Migration path

Keep n8n if it already runs the business workflow. Replace only the X/Twitter step that fails.

1. Keep the n8n workflow trigger and destination apps.
2. Replace a custom X node, unofficial scraper step, or manual export with Xquik. Use a REST call, extraction, webhook, or MCP tool.
3. Map Xquik fields into the existing n8n item shape.
4. Add explicit handling for `401`, `402`, `429`, and `5xx` responses.
