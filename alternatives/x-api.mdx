This page compares the official X (Twitter) API with Xquik. Xquik bills USD 0.00015 per tweet, profile, or
follower with pay-as-you-go credits. X's pricing page lists USD 0.005 per post
read. It also lists USD 0.010 per user read and USD 0.015 per post created. That
page showed these rates on 2026-10-15. Xquik charges only for delivered, unique,
filter-matching results. See [Xquik pricing](https://xquik.com) for
plans and credits.

See the [X (Twitter) API alternatives comparison](/twitter-api-alternatives) for more rivals ranked by price.

Use this guide to compare real X tasks. Search tweets, export followers and
replies, and retrieve profiles and timelines. Post tweets, send direct messages,
and monitor accounts or keywords. Send webhooks and connect apps or agents.

## <span className="nw">Source-backed</span> X API scope

X's official overview describes the X API as programmatic access to public conversation. Capabilities include reading posts, publishing content, managing users, and analyzing metrics and trends. They also include sending DMs, managing lists, and working with Spaces. The same overview recommends X API v2 for new projects.

{"\n"}

The official OAuth 2.0 overview covers app and user auth. It describes Bearer Token authentication tied to the developer App for reading public information. It also describes OAuth 2.0 Authorization Code Flow with PKCE for user-context access. Use that distinction when comparing tweet search with account actions. Account actions include posting, follows, DMs, and list management.

{"\n"}

The official Search Posts docs list <span className="cn">`GET /2/tweets/`<wbr />`search/`<wbr />`recent`</span> for last-7-day search. They list <span className="cn">`GET /2/tweets/search/all`</span> for full-archive search. All developers can use recent search, which returns up to 100 posts per request. Pay-per-use and Enterprise customers can use full-archive search. It returns up to 500 posts per request.

{"\n"}

The official Follows docs cover follower lookup and follow management. They list <span className="cn">`GET /2/users/:id/`<wbr />`followers`</span>, <span className="cn">`GET /2/users/:id/`<wbr />`following`</span>, <span className="cn">`POST /2/users/:id/`<wbr />`following`</span>, and <span className="cn">`DELETE /2/users/:`<wbr />`source_`<wbr />`user_id/`<wbr />`following/:`<wbr />`target_`<wbr />`user_id`</span>.

{"\n"}

The official pagination docs describe the standard loop. Request `max_results` and read the next-page cursor from `meta`. Send it on the following request, and repeat until the API returns no cursor. Use this when estimating engineering work for search, timeline, follower, and following exports.

{"\n"}

The official pricing docs describe credit-based pay-per-usage with per-resource reads and per-request writes. They also list Owned Reads at USD 0.001 per resource for eligible app-owned data. They list 24-hour UTC deduplication for billable resources. They cover Developer Console usage tracking, auto-recharge, and spending limits too.

## Official X API migration map

Use this map to move one API-backed workflow at a time. Keep the old call live.
Ship the matching Xquik call behind a feature flag. Then compare the record
shape, pagination cursor, export path, and output owner before switching.

<CardGroup cols={1}>

  <Card title="Auth & base URL" icon="key-round">

    Official X API calls use `https://api.x.com/2` plus Bearer or OAuth
    user-context auth. Xquik REST calls use <span className="cn">`https://`<wbr />`xquik.com/api/v1`</span> plus
    the `x-api-key` header.

  </Card>

  <Card title="Search posts" icon="search">

    Replace <span className="cn">`GET /2/tweets/`<wbr />`search/`<wbr />`recent`</span> or <span className="cn">`GET /2/tweets/search/all`</span> with
    <span className="cn">`GET /api/v1/x/`<wbr />`tweets/`<wbr />`search?q=`<wbr />`{query}`</span>. Keep supported X (Twitter) search operators
    in `q`, then resume with `cursor`.

  </Card>

  <Card title="Tweet lookup" icon="message-square">

    Replace `GET /2/tweets/:id` with <span className="cn">`GET /api/v1/x/`<wbr />`tweets/{id}`</span>. Replace
    <span className="cn">`GET /2/tweets?ids=...`</span> with <span className="cn">`GET /api/v1/x/`<wbr />`tweets?`<wbr />`ids=...`</span> for batches up
    to 100 tweet IDs.

  </Card>

  <Card title="User lookup" icon="user">

    Replace `GET /2/users/:id` and <span className="cn">`GET /2/users/by/`<wbr />`username/:`<wbr />`username`</span> with
    <span className="cn">`GET /api/v1/x/users/{id}`</span>. Xquik accepts a username or numeric user ID.
    Replace `GET /2/users?ids=...` with <span className="cn">`GET /api/v1/x/`<wbr />`users/`<wbr />`batch?`<wbr />`ids=...`</span>.

  </Card>

  <Card title="Timelines & mentions" icon="list-tree">

    Replace user timeline and mention timeline calls with
    <span className="cn">`GET /api/v1/x/`<wbr />`users/`<wbr />`{id}/`<wbr />`tweets`</span> and
    <span className="cn">`GET /api/v1/x/`<wbr />`users/`<wbr />`{id}/`<wbr />`mentions`</span>.

  </Card>

  <Card title="Followers & following" icon="users">

    Replace follower and following list reads with
    <span className="cn">`GET /api/v1/x/`<wbr />`users/`<wbr />`{id}/`<wbr />`followers`</span> and
    <span className="cn">`GET /api/v1/x/`<wbr />`users/`<wbr />`{id}/`<wbr />`following`</span>.

  </Card>

  <Card title="Engagement rows" icon="activity">

    Use <span className="cn">`GET /api/v1/x/`<wbr />`tweets/`<wbr />`{id}/`<wbr />`quotes`</span>,
    <span className="cn">`GET /api/v1/x/`<wbr />`tweets/`<wbr />`{id}/`<wbr />`retweeters`</span>,
    <span className="cn">`GET /api/v1/x/`<wbr />`tweets/`<wbr />`{id}/`<wbr />`favoriters`</span>, and
    <span className="cn">`GET /api/v1/x/`<wbr />`tweets/`<wbr />`{id}/`<wbr />`replies`</span> for quote, repost, like, or reply

    Official X (Twitter) API pagination reads `meta.next_token` and sends it back as

    accept it as `cursor`. For CSV, JSON, XLSX, Markdown, PDF, or TXT files,
    create an extraction job. Then call <span className="cn">`GET /api/v1/`<wbr />`extractions/`<wbr />`{id}/`<wbr />`export`</span>
    for those files.

## Migration path

Start with one API-backed task. Keep the current integration running. Meanwhile, compare output shape, latency, pagination, retries, exports, and alert delivery in Xquik.

{"\n"}

Keep the test small. Use 1 task, 1 output, 1 cost model, and 1 owner for the output. Switch only when the Xquik output matches the required records. It must also reduce integration work or cost.

{"\n"}

A coding agent can do the move with the [X API alternative Skill](https://github.com/Xquik-dev/x-api). It maps official X API v2 calls to Xquik endpoints. It names any call without one. It writes the client with API key auth, cursor pagination, and retries. The client also checks webhook signatures. It states the cost before a loop or a monitor runs.

```bash
npx skills add Xquik-dev/x-api
```

Price the real workload. On Xquik, Starter is USD 20/month with 140,000 credits. Top-ups are USD 0.00015/credit. Webhook and stored-event management cost no credits. Active monitors bill only while enabled. On X API, use the official per-resource and per-request prices in the Developer Console. Then add any engineering time for storage, exports, retries, dashboards, SDKs, and webhooks.
