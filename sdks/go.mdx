## Basic example

Search tweets and write durable JSON Lines handoff rows.

```go
package main

import (
	"context"
	"encoding/json"
	"os"

	"github.com/Xquik-dev/x-twitter-scraper-go"
	"github.com/Xquik-dev/x-twitter-scraper-go/option"
)

func main() {
	client := xtwitterscraper.NewClient(
		option.WithAPIKey(os.Getenv("X_TWITTER_SCRAPER_API_KEY")),
	)

	page, err := client.X.Tweets.Search(context.Background(), xtwitterscraper.XTweetSearchParams{
		Q:     "from:username webhook OR SDK",
		Limit: xtwitterscraper.Int(10),
	})
	if err != nil {
		panic(err)
	}

	encoder := json.NewEncoder(os.Stdout)
	for _, tweet := range page.Tweets {
		row := map[string]string{
			"tweet_id":        tweet.ID,
			"text":            tweet.Text,
			"author_username": tweet.Author.Username,
			"created_at":      tweet.CreatedAt,
		}

		if err := encoder.Encode(row); err != nil {
			panic(err)
		}
	}
}
```

## Tweet replies workflow to CSV, JSON, or XLSX

This workflow gets every reply under one tweet. It produces a saved extraction, JSON Lines handoff, or CSV, JSON, or XLSX export. Use it when a Go worker, queue consumer, or agent service needs that. It calls <span className="cn">`POST /extractions/`<wbr />`estimate`</span> through <span className="cn">`client.`<wbr />`Extractions.`<wbr />`EstimateCost`</span> and creates the job with <span className="cn">`client.`<wbr />`Extractions.Run`</span>. It reads rows with <span className="cn">`client.`<wbr />`Extractions.Get`</span> and downloads files with <span className="cn">`client.`<wbr />`Extractions.`<wbr />`ExportResults`</span>.

{"\n"}

Reuse the polling, `writeRows`, and `writeExport` helpers from the follower workflow. Only the tool type, target field, and output filenames change.

```go
targetTweetID := "1893704267862470862"

estimate, err := client.Extractions.EstimateCost(ctx, xtwitterscraper.ExtractionEstimateCostParams{
	ToolType:      xtwitterscraper.ExtractionEstimateCostParamsToolTypeReplyExtractor,
	TargetTweetID: xtwitterscraper.String(targetTweetID),
})
if err != nil {
	panic(err)
}
if !estimate.Allowed {
	panic("insufficient credits for reply extraction")
}

job, err := client.Extractions.Run(ctx, xtwitterscraper.ExtractionRunParams{
	ToolType:      xtwitterscraper.ExtractionRunParamsToolTypeReplyExtractor,
	TargetTweetID: xtwitterscraper.String(targetTweetID),
})
if err != nil {
	panic(err)
}

// Run the same polling loop from the follower workflow before exporting rows.
writeRows(ctx, client, job.ID, "xquik-replies.jsonl")
writeExport(ctx, client, job.ID, xtwitterscraper.ExtractionExportResultsParamsFormatCsv, "xquik-replies.csv")
writeExport(ctx, client, job.ID, xtwitterscraper.ExtractionExportResultsParamsFormatJson, "xquik-replies.json")
writeExport(ctx, client, job.ID, xtwitterscraper.ExtractionExportResultsParamsFormatXlsx, "xquik-replies.xlsx")
```

`reply_extractor` requires `TargetTweetID`. <span className="cn">`client.`<wbr />`Extractions.Get`</span> returns `Results`, `HasMore`, and `NextCursor`. The shared `writeRows` helper passes `NextCursor` back as `Cursor`. It repeats until all stored rows are written. Use `xquik-replies.jsonl` for queue replay or warehouse loads and `xquik-replies.json` for app ingestion. Use `xquik-replies.csv` for CRM import and `xquik-replies.xlsx` for analyst handoff. <span className="cn">`client.`<wbr />`Extractions.`<wbr />`ExportResults`</span> supports CSV, JSON, and XLSX for file handoff. The cost is 1 credit per reply extracted or returned.

## Cost, limits & retries

Tweet search costs 1 credit per tweet returned. Remaining credits may not cover the requested page. If so, the API can return fewer tweets than `Limit`. If 0 paid results are affordable, it returns <span className="cn"><span className="nw">`402 insufficient_`</span><wbr />`credits`</span>. Xquik rate-limits read calls. `429` responses include `Retry-After`.

{"\n"}

Generated Go methods return `error` for connection failures and non-success responses. Retry connection errors, 408, 409, 429, and 5xx responses with backoff. Do not retry 400, 401, 403, 404, or 422 until you fix the cause. The cause is a request, authentication, permission, or input issue.

</section>

## Error handling

Generated Go methods return `error` for connection failures and non-success API responses. Check the concrete error type from the SDK when you need status-code specific handling. Use the [error handling guide](/guides/error-handling) for response semantics.

{"\n"}

Common retryable cases are connection errors, 408, 409, 429, and 5xx responses.
