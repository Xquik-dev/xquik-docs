The Ruby SDK is for Ruby 3.2+ applications. Use it for typed REST access, retries, Yard docs, RBS, RBI, and connection pooling.

Use this page when Ruby code must search tweets. That code can be a Ruby app, Rails job, or Sidekiq worker. Use the page too for tweet exports to CSV, JSON Lines, or XLSX. The code can also export followers, upload media, send DMs, or monitor tweets. It can load records into a warehouse, CRM, queue, or agent.

| Ruby task        | SDK call                 | Save          |
| ---------------- | ------------------------ | ------------- |
| Search tweets    | `client.x.tweets.search` | `next_cursor` |
| Export followers | `client.extractions.run` | `job.id`      |

## Basic example

Search tweets and write durable JSON Lines handoff rows.

```ruby
require "json"
require "x_twitter_scraper"

client = XTwitterScraper::Client.new(
  api_key: ENV["X_TWITTER_SCRAPER_API_KEY"]
)

page = client.x.tweets.search(
  q: "from:username webhook OR SDK",
  limit: 10
)

page.tweets.each do |tweet|
  row = {
    tweet_id: tweet.id,
    text: tweet.text,
    author_username: tweet.author&.username,
    created_at: tweet.created_at
  }

  puts(JSON.generate(row))
end
```

## Tweet replies workflow to CSV, JSON, or XLSX

Use this workflow when Ruby code needs every reply under one tweet. That code can be a Ruby app, Rails job, Sidekiq worker, or agent tool. The replies can come as a saved extraction or a JSON Lines handoff. They can also come as a CSV, JSON, or XLSX file export.

{"\n"}

Reuse the polling, JSON Lines pagination, and export structure from the follower workflow. Only the tool type, target field, and filenames change.

```ruby
target_tweet_id = "1893704267862470862"

estimate = client.extractions.estimate_cost(
  tool_type: :reply_extractor,
  target_tweet_id: target_tweet_id
)

raise "Insufficient credits for reply extraction." unless estimate.allowed

job = client.extractions.run(
  tool_type: :reply_extractor,
  target_tweet_id: target_tweet_id
)

# Run the same polling and JSONL pagination loops from the follower workflow.
# Set the JSON Lines destination to File.open("xquik-replies.jsonl", "w").

csv_response = client.extractions.export_results(job.id, format_: :csv)
csv_response.rewind
File.binwrite("xquik-replies.csv", csv_response.read)

json_response = client.extractions.export_results(job.id, format_: :json)
json_response.rewind
File.binwrite("xquik-replies.json", json_response.read)

xlsx_response = client.extractions.export_results(job.id, format_: :xlsx)
xlsx_response.rewind
File.binwrite("xquik-replies.xlsx", xlsx_response.read)
```

`reply_extractor` requires `target_tweet_id`. `client.extractions.retrieve` returns `results`, `has_more`, and `next_cursor`. The shared pagination loop passes `next_cursor` back as `cursor`. Use `xquik-replies.jsonl` for queue replay or warehouse loads, and `xquik-replies.json` for app ingestion. Use `xquik-replies.csv` for CRM import and `xquik-replies.xlsx` for analyst handoff. `client.extractions.export_results` supports `:csv`, `:json`, and `:xlsx` for file handoff. The cost is 1 credit per reply extracted or returned.

## Cost, limits & retries

Tweet search costs 1 credit per tweet returned. If credits cannot cover a bounded `limit` request, the API can return fewer tweets. If credits cover 0 results, it returns `402 insufficient_credits`. Xquik rate-limits read calls. `429` responses include `Retry-After`.

{"\n"}

The client retries connection errors, timeouts, 408, 409, 429, and 5xx responses by default. Handle `XTwitterScraper::Errors::RateLimitError` with backoff. Fix 400, 401, 403, 404, or 422 responses before retrying.

</section>

## Error handling

All SDK errors inherit from `XTwitterScraper::Errors::APIError`.

<CardGroup cols={2}>

  <Card title="400 Bad request" icon="triangle-alert">

    Raises `BadRequestError`.

  </Card>
  <Card title="401 Unauthenticated" icon="lock">

    Raises `AuthenticationError`.

  </Card>
  <Card title="403 Permission denied" icon="shield">

    Raises `PermissionDeniedError`.

  </Card>
  <Card title="404 Not found" icon="circle-x">

    Raises `NotFoundError`.

  </Card>
  <Card title="422 Unprocessable entity" icon="triangle-alert">

    Raises `UnprocessableEntityError`.

  </Card>
  <Card title="429 Rate limited" icon="gauge">

    Raises `RateLimitError`.

  </Card>
  <Card title="5xx server error" icon="server">

    Raises `InternalServerError`.

  </Card>
</CardGroup>

```ruby
begin
  account = client.account.retrieve
rescue XTwitterScraper::Errors::APIConnectionError => e
  warn("Connection failed: #{e.cause}")
rescue XTwitterScraper::Errors::APIStatusError => e
  warn("HTTP #{e.status}")
end
```

## Pagination

Paginated responses expose fields such as `has_next_page`. Pass the endpoint's cursor fields when requesting more pages.

```ruby
page = client.x.tweets.search(q: "xquik", limit: 20)
puts("More results are available") if page.has_next_page
```
