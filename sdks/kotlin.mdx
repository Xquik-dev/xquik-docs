## Distinct Kotlin fit

Use Kotlin for nullable models, builders, sync and async calls, and JVM workers. Use Java for Java services or C# for .NET.

{"\n"}

Use the Kotlin SDK for generated JVM models, nullable values, and builders. Use
it for sync calls, async calls, typed exceptions, retries, and file upload
helpers. It fits Ktor workers, Spring jobs, queue consumers, and scheduled
tasks. Search tweets, export followers, monitor tweets, post media, upload
files, or send direct messages. Hand tweet, follower, reply, and profile rows to
downstream systems.

| Kotlin task               | SDK call                                       | Save                                             |
| ------------------------- | ---------------------------------------------- | ------------------------------------------------ |
| Search tweets             | `client.x().tweets().search`                   | Store `page.nextCursor()` after every page.      |
| Estimate exports          | `client.extractions().estimateCost`            | Store the estimate and `allowed()` decision.     |
| Start an extraction       | `client.extractions().run`                     | Save `job.id()` immediately.                     |
| Retrieve saved rows       | `client.extractions().retrieve`                | Keep `nextCursor()` while `hasMore()` is true.   |
| Export CSV, JSON, or XLSX | `client.extractions().exportResults`           | Record the job ID, format, and file destination. |
| Create a tweet            | `client.x().tweets().withRawResponse().create` | Store the write action ID and terminal state.    |

## Install

Add the Gradle dependency from [Maven Central](https://central.sonatype.com/artifact/com.xquik.api/x-twitter-scraper-kotlin).

```kotlin
implementation("com.xquik.api:x-twitter-scraper-kotlin:0.9.3")
```

Or add the Maven dependency.

```xml
<dependency>
  <groupId>com.xquik.api</groupId>
  <artifactId>x-twitter-scraper-kotlin</artifactId>
  <version>0.9.3</version>
</dependency>
```

## Basic example

Search tweets and write durable JSON Lines handoff rows.

```kotlin
import com.fasterxml.jackson.databind.ObjectMapper
import com.x_twitter_scraper.api.client.XTwitterScraperClient
import com.x_twitter_scraper.api.client.okhttp.XTwitterScraperOkHttpClient
import com.x_twitter_scraper.api.models.PaginatedTweets
import com.x_twitter_scraper.api.models.SearchTweet
import com.x_twitter_scraper.api.models.x.tweets.TweetSearchParams

val client: XTwitterScraperClient = XTwitterScraperOkHttpClient.fromEnv()
val objectMapper = ObjectMapper()

val params: TweetSearchParams = TweetSearchParams.builder()
    .q("from:username webhook OR SDK")
    .limit(10L)
    .build()

val page: PaginatedTweets = client.x().tweets().search(params)

for (tweet: SearchTweet in page.tweets()) {
    val row = linkedMapOf<String, Any?>(
        "tweet_id" to tweet.id(),
        "text" to tweet.text(),
        "author_username" to tweet.author()?.username(),
        "created_at" to tweet.createdAt(),
    )

    println(objectMapper.writeValueAsString(row))
}
```

## Tweet replies workflow to CSV, JSON, or XLSX

Use this workflow when a Kotlin worker needs every reply as a durable file. The parent can be a campaign, support thread, launch post, or incident update. `reply_extractor` requires `targetTweetId`. Estimate first, run the job, and poll `retrieve`. Then export the completed job as CSV, JSON, or XLSX.

{"\n"}

Reuse the follower export loop above. Change only the required target, tool type, and output names.

```kotlin
val targetTweetId = "1893704267862470862"

val estimate: ExtractionEstimateCostResponse = client.extractions().estimateCost(
    ExtractionEstimateCostParams.builder()
        .toolType(ExtractionEstimateCostParams.ToolType.REPLY_EXTRACTOR)
        .targetTweetId(targetTweetId)
        .build()
)

val job: ExtractionRunResponse = client.extractions().run(
    ExtractionRunParams.builder()
        .toolType(ExtractionRunParams.ToolType.REPLY_EXTRACTOR)
        .targetTweetId(targetTweetId)
        .build()
)

val pageParams = ExtractionRetrieveParams.builder()
    .id(job.id())
    .limit(1000L)

if (!cursor.isNullOrEmpty()) {
    pageParams.cursor(cursor)
}

val page: ExtractionRetrieveResponse = client.extractions().retrieve(pageParams.build())
```

Store `job.id()` before polling. A queue retry uses it to resume the read. After completion, it can repeat the export.

```kotlin
client.extractions().retrieve(job.id())
client.extractions().exportResults(...)
```

Stream `page.results()` to <span className="cn">`Paths.get(`<wbr /><span className="nw">`"xquik-replies.`</span><wbr />`jsonl")`</span>. Keep `page.nextCursor()` as the checkpoint while streaming replies to JSON Lines. Pass it back as `cursor` on the next page request. The code above builds that request with the `ExtractionRetrieveParams` builder.

{"\n"}

Keep the same `estimate.allowed()` credit branch from the follower export workflow before calling `run`.

{"\n"}

Export the completed job with the same helper used above.

```kotlin
client.extractions().exportResults(
    ExtractionExportResultsParams.builder()
        .id(job.id())
        .format(ExtractionExportResultsParams.Format.CSV)
        .build()
).use { export ->
    Files.copy(export.body(), Paths.get("xquik-replies.csv"), StandardCopyOption.REPLACE_EXISTING)
}
```

Repeat the export with each format to write <span className="cn">`Paths.get(`<wbr /><span className="nw">`"xquik-replies.`</span><wbr />`json")`</span> and <span className="cn">`Paths.get(`<wbr /><span className="nw">`"xquik-replies.`</span><wbr />`xlsx")`</span>.

```kotlin
ExtractionExportResultsParams.Format.JSON
ExtractionExportResultsParams.Format.XLSX
```

Use `xquik-replies.jsonl` for queue replay or warehouse loads and `xquik-replies.json` for app ingestion. Use `xquik-replies.csv` for CRM import and `xquik-replies.xlsx` for analyst handoff. The cost is 1 credit per reply extracted or returned.

## Error handling

The Kotlin SDK uses the same generated exception hierarchy as the Java SDK.

- **<span className="nw">400 Bad</span> request.** Throws `BadRequestException`.
- **<span className="nw">401 Unauthorized</span>.** Throws `UnauthorizedException`.
- **<span className="nw">403 Permission</span> denied.** Throws `PermissionDeniedException`.
- **<span className="nw">404 Not</span> found.** Throws `NotFoundException`.
- **<span className="nw">422 Validation</span> error.** Throws `UnprocessableEntityException`.
- **<span className="nw">429 Rate</span> limited.** Throws `RateLimitException`.
- **5xx server error.** Throws `InternalServerException`.

Connection and I/O failures use `XTwitterScraperIoException`. All SDK exceptions inherit from `XTwitterScraperException`.
