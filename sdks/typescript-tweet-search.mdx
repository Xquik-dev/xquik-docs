## Tweet search workflow to JSON Lines, CSV, or XLSX

This job is for Node.js, Bun, and queue workers that need searchable tweet data. They need it in a stable handoff format. The format is for queues, data lakes, analyst CSV files, or XLSX workbooks. It calls `GET /x/tweets/search` through `client.x.`<span className="cn"><wbr />`tweets.`<wbr />`search`</span> with the generated `TweetSearchParams` shape. It writes each returned tweet as one projected JSON object per line.

```ts
import XTwitterScraper from "x-twitter-scraper";

const client = new XTwitterScraper();
const query = "from:username webhook OR SDK";
let cursor: string | undefined;
let pageIndex = 0;

while (true) {
  const pageCursor = cursor ?? null;
  const page = await client.x.tweets.search({
    q: query,
    queryType: "Latest",
    cursor,
  });

  for (const tweet of page.tweets) {
    const row = {
      source: "xquik.typescript.search",
      query,
      tweet_id: tweet.id,
      text: tweet.text,
      author_id: tweet.author?.id ?? null,
      author_username: tweet.author?.username ?? null,
      author_name: tweet.author?.name ?? null,
      created_at: tweet.createdAt ?? null,
      like_count: tweet.likeCount ?? 0,
      reply_count: tweet.replyCount ?? 0,
      retweet_count: tweet.retweetCount ?? 0,
      quote_count: tweet.quoteCount ?? 0,
      view_count: tweet.viewCount ?? 0,
      bookmark_count: tweet.bookmarkCount ?? 0,
      is_note_tweet: tweet.isNoteTweet ?? false,
      page_index: pageIndex,
      page_cursor: pageCursor,
      next_cursor: page.next_cursor || null,
      has_next_page: page.has_next_page,
    };

    process.stdout.write(`${JSON.stringify(row)}\n`);
  }

  if (!page.has_next_page || !page.next_cursor) {
    break;
  }

  cursor = page.next_cursor;
  pageIndex += 1;
}
```

The generated params map directly to the REST endpoint.

## Returned data & handoff

`client.x.`<span className="cn"><wbr />`tweets.`<wbr />`search`</span> returns `PaginatedTweets`.

<CardGroup cols={2}>

  <Card title="page.tweets" icon="message-square-text">

    JSON field `tweets`. Contains tweet records with `id`, `text`, optional `author`, and `createdAt`. Records also carry `likeCount`, `replyCount`, `retweetCount`, `quoteCount`, `bookmarkCount`, `viewCount`, and `isNoteTweet` when available.

  </Card>
  <Card title="page.has_next_page" icon="circle-check">

    TypeScript field `page.has_next_page`. JSON field `has_next_page`. Tells your worker whether another page exists.

  </Card>
  <Card title="page.next_cursor" icon="arrow-right">

    JSON field `next_cursor`. Store it only when `page.has_next_page` is true. For bounded pulls that return fewer tweets than `limit`, pass it back as `cursor`. Send the same query, filters, `queryType`, and `limit` with it.

  </Card>
</CardGroup>

Project `page.tweets` into JSON Lines rows in `xquik-tweet-search.`<span className="cn"><wbr />`jsonl`</span> for queues and data lakes. You can also transform the same projected records into CSV for analysts. When account teams need spreadsheets, produce XLSX from those rows. Store `tweet_id`, `author_username`, engagement counts, `page_index`, `page_cursor`, `next_cursor`, and `has_next_page`. With them, workers resume from the last saved cursor without replaying raw SDK objects. For explicit `limit` pulls, resume with the same query, filters, `queryType`, and `limit`. Only `cursor` changes.
