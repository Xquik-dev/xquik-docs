## Distinct Python fit

Choose Python for typed synchronous or asynchronous clients. It fits scripts, notebooks, workers, pandas pipelines, and agent tools. Use TypeScript when the runtime and downstream models are Node.js-based.

{"\n"}

Use the Python SDK for typed sync or async access to Xquik. It works from scripts, notebooks, workers, agent tools, and backend services.

{"\n"}

Use this page when Python must search tweets. Use it too for tweet exports to CSV, JSON Lines, or XLSX. Python can export followers, post tweets, upload media, or send DMs. It can also monitor tweets. It can load records into pandas, a warehouse, a queue, CRM, or an agent.

## Basic example

Search tweets and write durable JSON Lines handoff rows.

```python
import json
import sys

from x_twitter_scraper import XTwitterScraper

client = XTwitterScraper()

page = client.x.tweets.search(
    q="from:username webhook OR SDK",
    limit=10,
)

for tweet in page.tweets:
    row = {
        "tweet_id": tweet.id,
        "text": tweet.text,
        "author_username": tweet.author.username if tweet.author else None,
        "created_at": tweet.created_at,
    }
    sys.stdout.write(json.dumps(row, ensure_ascii=False) + "\n")
```

Async clients use the same generated method names.

```python
import asyncio
import json
import sys

from x_twitter_scraper import AsyncXTwitterScraper

client = AsyncXTwitterScraper()

async def main() -> None:
    page = await client.x.tweets.search(q="xquik", limit=10)
    for tweet in page.tweets:
        row = {
            "tweet_id": tweet.id,
            "text": tweet.text,
            "author_username": tweet.author.username if tweet.author else None,
            "created_at": tweet.created_at,
        }
        sys.stdout.write(json.dumps(row, ensure_ascii=False) + "\n")

asyncio.run(main())
```

## Tweet replies workflow to CSV, JSON, or XLSX

Use this workflow when Python code needs every reply under one tweet. It fits a script, notebook, worker, or agent tool. The replies come as a saved extraction or a JSON Lines handoff. They can also come as a CSV, JSON, or XLSX file export. It uses `client.extractions.estimate_cost`, `run`, `retrieve`, and `export_results`.

{"\n"}

Reuse the polling, row pagination, and export structure from the follower workflow. Only the tool type, target field, and output filenames change.

```python
target_tweet_id = "1893704267862470862"
estimate = client.extractions.estimate_cost(
    tool_type="reply_extractor",
    target_tweet_id=target_tweet_id,
)

if not estimate.allowed:
    raise RuntimeError("Insufficient credits for reply extraction.")

job = client.extractions.run(
    tool_type="reply_extractor",
    target_tweet_id=target_tweet_id,
)

# Run the same polling and JSONL pagination loops from the follower workflow.
# Set the JSON Lines destination to Path("xquik-replies.jsonl").

client.extractions.export_results(job.id, format="csv").write_to_file(
    Path("xquik-replies.csv"),
)
client.extractions.export_results(job.id, format="json").write_to_file(
    Path("xquik-replies.json"),
)
client.extractions.export_results(job.id, format="xlsx").write_to_file(
    Path("xquik-replies.xlsx"),
)
```

`reply_extractor` requires `target_tweet_id`. `client.extractions.retrieve` returns `results`, `has_more`, and `next_cursor`. The shared pagination loop passes `next_cursor` back as `cursor`. Use `xquik-replies.jsonl` for queue replay or warehouse loads, and `xquik-replies.json` for app ingestion. Use `xquik-replies.csv` for CRM import and `xquik-replies.xlsx` for analyst handoff. `client.extractions.export_results` supports `csv`, `json`, and `xlsx` for file handoff. The cost is 1 credit per reply extracted or returned.

## Cost, limits & retries

Tweet search costs 1 credit per tweet returned. If credits cannot cover a bounded `limit` request, the API can return fewer tweets. If credits cover no results, it returns `402 insufficient_credits`. Xquik rate-limits read calls. `429` responses include `Retry-After`.

{"\n"}

The client retries connection errors, 408, 409, 429, and 5xx responses by default. Handle `RateLimitError` with backoff. Fix 400, 401, 403, 404, or 422 responses before retrying.

</section>

## Error handling

All SDK exceptions inherit from `x_twitter_scraper.APIError`.

<CardGroup cols={2}>

  <Card title="400 Bad request" icon="triangle-alert">

    Raises `BadRequestError`.

  </Card>
  <Card title="401 Unauthenticated" icon="lock">

    Raises `AuthenticationError`.

  </Card>
  <Card title="403 Permission denied" icon="shield">

  <Card title="404 Not found" icon="circle-x">

    Raises `NotFoundError`.

  </Card>
  <Card title="422 Unprocessable entity" icon="triangle-alert">

    Raises `UnprocessableEntityError`.

  </Card>
  <Card title="429 Rate limited" icon="gauge">

    Raises `RateLimitError`.

  </Card>
  <Card title="5xx server error" icon="server">

    Raises `InternalServerError`.

  </Card>
</CardGroup>

```python
import x_twitter_scraper

try:
    account = client.account.retrieve()
except x_twitter_scraper.APIConnectionError as exc:
    print(f"Connection failed: {exc.__cause__}")
except x_twitter_scraper.APIStatusError as exc:
    print(f"HTTP {exc.status_code}")
```

The client retries connection errors, 408, 409, 429, and 5xx responses by default. Pass `max_retries` when constructing the client to change retry behavior.

## Pagination

List endpoints return page models with `has_next_page` and cursor fields.

```python
page = client.x.tweets.search(q="xquik", limit=20)

if page.has_next_page:
    print("More results are available")
```
