<Info>

Omit `mode` to get the fullest results. The response shape stays the same.
Pass `next_cursor` back unchanged as `cursor`. Keep the same endpoint, target,
query, and filters.

</Info>

Existing unprefixed cursors keep their legacy behavior. `after`, `limit`, and
`pageSize` aliases also keep working. Billing still counts only returned rows.
Use `mode=standard` only to keep the legacy pagination.

A page can be empty or underfilled. Continue while `has_next_page` is `true`.
Stop only after the response reports `has_next_page=false`.

First-page requests do not support `Idempotency-Key` retries.
Repeating a cursorless request starts a separate extraction.
Results returned by that extraction incur their normal charges.
Save each response before requesting its next page.
A cursor sent again within 10 minutes returns the same page at no charge.
After 10 minutes, you cannot replay earlier or terminal responses.

If automatic coverage is busy, an initial request returns a standard data page.
Live coverage cursors remain atomic. A cursor sent again while its page is
still loading returns that page at no charge.
Other repeats return `409 coverage_cursor_unavailable` with exact `Retry-After`
seconds. Wait, then send the same cursor again.
Repeated busy responses never authorize restarting with another cursor.

Expired, superseded, or identity-mismatched cursors return
`410 coverage_cursor_gone`. So does a cursor sent again after 10 minutes. The
response omits `Retry-After`. Restart without a cursor. Keep received results.
Deduplicate restarted results by `id`.
Malformed cursors return `400 invalid_coverage_cursor`. Restart without them.
