<section>

## Step 1. Install the SDK

```bash
npm i mppx viem
```

The `mppx` package provides both client and server utilities. You only need the client. `viem` manages the wallet account.

</section>

<section>

## Step 2. Set up a Tempo wallet

You need a Tempo wallet funded with USDC. The `mppx` client also needs the wallet's raw hex private key.

{"\n"}

**Path A. CLI only.** Recommended for agents.

```bash
mppx account create             # generates a local keychain-backed account
mppx account export             # prints the hex private key (0x...)
```

Fund the account's address with USDC on Tempo. Then copy the exported key into `TEMPO_PRIVATE_KEY`.

{"\n"}

**Path B. Web wallet as a USDC source.**

{"\n"}

Use [wallet.tempo.xyz/welcome](https://wallet.tempo.xyz/welcome) as a hosted UI to buy & send USDC. Run `mppx account create` to create a local account and copy its address. Send USDC from the web wallet to that address. Then run `mppx account export` to get the hex key.

{"\n"}

You cannot import the web wallet into `mppx`. It is a funding source, not a key source.

> **Warning.** Never commit your private key to version control. Load it from an environment variable.

</section>

<section>

## Step 3. Make a charge request

Look up a single tweet. The SDK intercepts 402 responses, pays via Tempo, and retries automatically.

```typescript
import { Mppx, tempo } from "mppx/client";
import { privateKeyToAccount } from "viem/accounts";

// Configure the MPP client. This patches global fetch
// to automatically handle 402 Payment Required challenges
Mppx.create({
  methods: [
    tempo({
      account: privateKeyToAccount(process.env.TEMPO_PRIVATE_KEY as `0x${string}`),
    }),
  ],
});

// Now any fetch to an MPP-enabled endpoint auto-pays
const response = await fetch("https://xquik.com/api/v1/x/tweets/1893456789012345678");
const data = await response.json();
console.log(data.tweet.text);
```

`Mppx.create()` patches the global `fetch` function. A direct MPP request can return 402 with a `WWW-Authenticate: `<span className="cn"><wbr />`Payment`</span> header. The SDK then pays the requested amount. It sends the request again with an `Authorization: `<span className="cn"><wbr />`Payment`</span> credential. Every response after accepted payment includes a `Payment-Receipt` header confirming settlement.

</section>

## Step 4. Raw HTTP flow without the SDK

Without the `mppx` SDK, implement the protocol yourself.

{"\n"}

**Step 1.** Request the endpoint.

```bash
curl -i https://xquik.com/api/v1/x/tweets/1893456789012345678
```

**Step 2.** Receive the 402 challenge.

```text
HTTP/2 402
WWW-Authenticate: Payment id="abc...", realm="xquik.com", method="tempo", intent="charge", request="eyJhbW91bnQiOi..."
```

The `request` parameter is a base64url-encoded JSON object. It holds the amount, currency, and recipient address.

{"\n"}

The `application/`<span className="cn"><wbr />`problem+json`</span> body also includes an optional `payment_`<span className="cn"><wbr />`options.`<wbr />`guest_`<wbr />`wallet.`<wbr />`create_`<wbr />`checkout`</span> action. It does not replace the MPP header. The failed request creates no checkout. Ignore it when completing MPP. Use it only after a user explicitly picks and confirms a guest wallet. Its amount is USD 10 to 250.

{"\n"}

**Step 3.** Pay and retry.

{"\n"}

After completing the Tempo payment, retry the request with the payment credential.

```bash
curl -i https://xquik.com/api/v1/x/tweets/1893456789012345678 \
  -H "Authorization: Payment eyJjaGFsbGVuZ2UiOnsi..."
```

The `Authorization: `<span className="cn"><wbr />`Payment`</span> value is a base64url-encoded JSON object. It holds the original challenge and your payment proof.

{"\n"}

**Step 4.** Receive the response and receipt.

```text
HTTP/2 200
Payment-Receipt: eyJzdGF0dXMiOiJzdWNjZXNzIiwi...
Content-Type: application/json

{"tweet": {"id": "1893456789012345678", "text": "..."}}
```

The `Payment-Receipt` header confirms settlement. Check the HTTP status and response body separately. Accepted payments include a receipt on non-2xx responses too.

</section>
